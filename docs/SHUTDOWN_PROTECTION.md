# 关闭保护与当前预览架构（2026-10-30）

## 如何退出

从根目录 `Start-WISEYE-Studio.vbs` 启动后，关闭主窗口会停止本次启动的训练端，再由会话管理器尝试降落所有活动无人机、关闭 UE、飞控和随它们启动的子进程。直接关闭 UE 时，也会关闭本次主界面、训练端和后台服务。关闭过程中请等待清理完成再重新启动；启动脚本会拒绝重复占用端口。

存在未提交传感器草稿时，主窗口保留原有退出确认。不会自动把草稿应用到设备。训练端正常关闭会等待正在进行的采样/保存结束；没有响应时会在期限后关闭进程树，因此强制退出或断电不能保证最后一组数据完整，训练前仍需完整性校验。

“连接 UE”属于接入已有仿真，关闭这个独立控制台只清理其自身和它启动的训练端，不关闭外部 UE。手工启动的训练端或已有其他窗口不因被激活而获得本次会话的所有权。发布版也使用同一进程所有权组件，但旧已打包 EXE 不会随源码修改自动更新。

## 实现约束

- `core/process_job.py`：Windows Job，先挂起创建、加入 Job，再恢复执行，覆盖虚拟环境 Python 的二次启动。关闭 Job/所有者进程退出时清理其子进程，不按 `python.exe` 或 `UnrealEditor.exe` 名称批量结束。
- `apps/desktop_app/preview_session.py`：源码根入口的会话所有者，监测 UE、飞控和主窗口退出；保留已有启动阶段文件与自动连接。
- `runtime_manager.py`：桌面“启动仿真”按钮的所有者，兼容源码和发布版；关闭等待在后台完成，GUI 不阻塞。
- `training_launcher.py`：记录本次训练进程 Job，先向所属窗口发送关闭请求，再等待或超时兜底。
- `session_shutdown.py`：先核对原生端/飞控 `run_id`，再恢复原生仿真推进、按 `drone_id` 下发降落。降落 ACK 最多等待8秒，超时继续观察状态；短暂轮询错误重试，总等待默认30秒。未确认 ready 时只记为超时清理，不声称成功降落。run_id 改变即停止控制。
- `core/local_rpc.py`：每次 RPC 有总时间上限，避免慢速分块无限延长退出。

会话日志：`E:\Projects\WISEYE-IR-Work\preview-data\logs\session.log`。重启后的首次城市加载可能明显慢于缓存热启动；关闭保护不会消除资源加载或着色器准备耗时。

## 预览方案的后续变更

最初已实现快速最新帧和低频 GT 分离，历史验证见 `evidence/session-video-20261029`：视频约9FPS、同步保存12组且不会把旧 GT 贴到新视频。

随后用户另行要求统一界面并提高 GT 采集速率，当前产品已采用后续方案，**不恢复旧的“实时视频/标注样本”切换**。训练端仍为同组图像与 GT，最新单槽避免积压、显示与保存独立限频；默认预览上限5、保存1，本机实际约4.5FPS。GT框开关只控制叠框，不跳过 GT 采集。仿真工作台的普通传感器预览继续走最新 JPEG 缓存。详见 [GT速率与统一预览](GT_RATE_AND_UNIFIED_PREVIEW.md)。

当前并非30FPS训练预览。下一步若再次需要更高帧率，应在保留统一界面的前提下明确是否允许预览使用无 GT 的独立帧，再优化 GPU 读回、图像编码、往返请求和传输；不得直接提高数字或重复旧帧冒充达标。

## 验证

自动回归覆盖：外部会话不被控制、按所有无人机 ID 降落、迟到 ACK/短暂状态超时继续等待、Job 包含 Python 后代且不影响外部进程。实机关闭回归脚本 `tests/verify_session_lifecycle_live.py` 会关闭待测预览，仅在明确用于验收的会话中运行。最新证据目录：`docs/evidence/shutdown-final-20261030`。

最终验收：94核心、54Qt通过；空中关闭主窗口后确认降落，整套退出13.21秒；直接关闭UE后整套退出3.79秒。两次所属进程均无残留。UE已被直接关闭时无法再执行降落，此路径仅保证清理。测试后无额外常规预览运行，双击根VBS即可启动。未重新打包或推送GitHub。
