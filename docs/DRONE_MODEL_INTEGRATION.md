# 新无人机模型接入规范（给用户与 AI）

固定翼已单独接入：`fixedwing`、用户指定机长80cm，当前为原生运动学巡航，不复用四旋翼物理或旋翼编号。下方四旋翼专用步骤不应机械套用固定翼；当前源码目录为 `E:\Projects\WISEYE`，详 [中英文与固定翼](LANGUAGE_FIXEDWING.md)。

适用当前 WISEYE 源码。新模型不是把文件放入 Models 就会自动出现在菜单中；必须完成资产、程序注册、旋翼、热像、灯光及运行验收。

## 提供什么文件

当前实际导入流程支持 **FBX 静态网格**，首选 `.fbx` 加完整贴图目录（常见 `.fbm`）。已有实例：`Models/Mavic3_black.fbx`、`Models/Avata_black.fbx`。材质、纹理必须随模型提供，禁止使用只有本机才有的绝对纹理路径。

运行时使用 UE 导入生成的 `.uasset`，不直接读取 FBX。已有 UE 资产应提供与本工程兼容的完整迁移资源及依赖，而非单独复制一个网格文件。OBJ、GLB/GLTF、BLEND、USD 等文件没有接入当前自动脚本；拿到这些文件时先转换/建立并验证相应导入流程，不宣称系统可以直接加载。

建议按 `Models/<model_id>/` 单独存放后续新模型；保留原件。运行资产使用 `/Game/WISEYE/DroneModels/<ModelName>/`，不能覆盖通用 Mesh 名称或现有型号。

## 模型和参数交付要求

| 内容 | 要求 |
|---|---|
| 唯一编号 | 例如 `new_quad`，与中文名称分开，禁止复用已有编号 |
| 尺寸与单位 | 提供真实长宽高、展开/折叠状态、是否包含桨叶/护圈；引擎工作单位 cm |
| 机身 | 独立于可转动桨叶，正确法线、UV、材质；护圈属于机身 |
| 旋翼 | 四个可独立旋转的网格及各电机轴心；合并网格需可识别并拆分，否则不能承诺真实转桨 |
| 朝向 | 指明机头、上方、左右与原点；标出旋翼编号与转向，不能靠文件名猜测 |
| 灯位 | 建议提供 `NavRedLeft`、`NavGreenRight` 安装点/插槽；也可提供相对机身中心的厘米坐标 |
| 热区 | 电机、电池位置和大致尺寸；不确定时说明是近似，禁止把光学灯当作热源 |
| 动力学 | 只换外观可复用 `shared_quadrotor`；若要机型性能，另给质量、惯量、推力/转矩、阻力、电机配置等并重新验证 |

当前灯位实现：四个电机轴下方的小灯珠，机体左侧红、右侧绿；Mavic 直径0.9cm，Avata 0.6cm。现有型号使用近似安装点，非原厂实物结构复刻。新增型号必须显式完成对应灯位分支或改用插槽，不能沿用错误的 Mavic 安装点。

## AI 必须完成的修改

1. 先读 `AGENTS.md`、`docs/AI_HANDOFF.md`、`WISEYE_ProjectPlan.md` 并检查工作区；本机 F 为唯一源，E 为构建副本。保留用户当前 Fleet 数量、位置、朝向和已改代码；不得为了加型号重建城市。
2. 在 `ue5/scripts/` 增加幂等导入/构建脚本。参考 `import_drone_models.py`、`build_avata_rotors.py`、`build_rotor_blur.py`、`build_navigation_lights.py`。Avata 的特定网格 UUID 和尺寸不能当成通用算法直接复制。保存生成资产并带齐依赖。
3. 把尺寸加入 `ue5/WISEYE/Config/WISEYE/device_dimensions.json`，完成**实际应用缩放**和校验；仅增加 JSON 不会自动缩放全部运行组件。不得运行旧脚本将已有 Mavic/Avata/PTZ 尺寸改回旧值。
4. 修改 `core/devices.py` 的 MODELS、`core/models.py` 的状态校验、`apps/desktop_app/workbench_v3.py` 的型号选择。搜索所有已有型号分支，补齐遗漏；不能只增加下拉选项。
5. 修改 `ue5/WISEYE/Source/test/WiseEyeFleet.cpp` 的型号验证；在 `WiseEyeDemo.h/.cpp` 的 `InitializeDroneModels`、`SetDroneModel`、`StepRotors` 加入资源加载、显隐、旋翼转向与物理电机编号映射。模型切换要清除旧外观、旧旋翼/模糊盘，不能残留或重复创建组件。
6. 在 `StepNavigationLights` 加入灯位与尺寸。灯跟随真实姿态、默认夜间自动闪烁，不能用每帧重新生成组件的方式实现；每个实例独立，IR 相机必须隐藏灯珠。不要添加高成本大范围投射光。
7. 修改 `WiseEyeSensors.cpp` 的 `ConfigureThermalActors` / `UpdateThermalProjection`，补充机身、旋翼、电机、电池映射。保留当前 facade 成像；灯珠跳过热分类。VIS 的有形灯珠可进入深度轮廓，Bloom 光晕不应扩大实体 GT；IR 深度/图像均隐藏灯珠，不能伪造灯光热斑。
8. 验证放置草稿完整显示新外形、尺寸与朝向正确，草稿不进入任何训练图像。多实例创建和型号切换均正确。保留 AirSim 姿态控制、真实 RPM 转桨与碰撞规则。
9. 检查 `training_client/storage.py` 的型号名称映射；协议、GT 的 `model_id`、场景型号和保存命名使用新编号。保留 visible/IR 对应保存、空标签负样本、遮挡策略。
10. 检查 Cook 目录与新增资产是否入包。当前 DefaultGame.ini 已包含 `/Game/WISEYE/DroneModels` 和基础形状；新路径不在其中时另补。编译 Editor 后才运行，并同步必要资产至源目录。旧 Shipping 包不会因源码修改自动更新。

## 必须验收并报告

- 网格/贴图无缺失，长宽高、机头方向、电机轴心符合参数，四旋翼不绕机身公转。
- 原型号 → 新型号 → 原型号切换，无残留灯珠/桨叶/碰撞；多实例型号互不影响。
- 真实起飞、悬停、转向、降落，四路 RPM 随动力学变化，最终 ready 且四 RPM 为0。
- 白天无闪烁灯，夜间红/绿/全灭阶段都出现；灯位随姿态，无持续积累组件；切回白天关闭。
- VIS 与 IR 同帧配对、各自 GT 正确；完全遮挡无 GT、部分遮挡/出画按策略、无目标帧保存为空 txt。
- 夜间灯光能进入 VIS；IR 不出现灯珠造成的闪烁热斑。检查近距和远距，不承诺子像素灯珠远距必然可见。
- 新型号训练保存命名、追加已有目录、界面预览 GT 开关均正常。
- 报告实际编译与测试证据、未测试项目、动力学是否共用。测试仅操作自有实例，结束恢复环境/型号/相机并降落；不关用户编辑器，不提交或发布未经授权的内容。
