# 人车预载、实例显示与轻量加载界面

## 操作

启动仿真或切换地图时显示深色加载覆盖层，沿用WISEYE蓝色、几何线条和大幅W标记。加载光带为活动指示，没有伪造百分比；阶段由实际进程和状态回复驱动：引擎启动、地图装载、目标资源准备、设备连接。包括地图流送、资产/着色器编译、人车预载及生成、首帧接收和连续3个独立硬件样本的稳定确认。资源未就绪时不会只凭计时器结束加载。

可点击“返回工作台”后台加载，再点击状态栏的加载按钮查看详情。隐藏时动画和计时器停止；失败显示实际原因，停止所属会话时退出加载。覆盖层显示期间清除持续操控输入并拦截移动键，F11仍可切换全屏。后台没有额外渲染视角或视频。

## 运行优化

原先仅降低全局Crowd LOD预算并不充分：资产自己的显示模板仍可能在近处创建完整角色。本轮从配置模板本身入手，异步预载Mass实体配置，保留加载引用，预构建实体模板；被动行人、行驶车辆和停放车辆的高/中LOD统一采用已有静态网格实例显示。行人实例仍使用原有VAT动画，保留原生人行路径和车辆道路逻辑，停用保留低精度Actor的选项，并分散首次显示更新。

人群实例预算支持当前密度上限，实例可见距离扩展到600m，适合航拍。并非整城所有目标都使用完整角色、物理车辆或高频行为；没有新增可驾驶汽车或近距离人物交互。原有UE实例系统承担复用，本轮未另造完整GTA式对象池、地图流送引擎或自定义AI调度器。

仅对运行中的目标配置做内存修改，不保存或覆盖原始CitySample资产。开关、密度、目标ID接口保留，人口关闭时不主动预载对应配置；预载出错会暴露preload_error并给出加载失败提示。已有资产在当前世界中保留引用以减少再次加载，可能增加常驻内存。启动就绪检查现在适用于大小城市，避免小城在目标资源未准备时提前进入。Runtime硬件状态新增shader_compile_jobs。

## 验证及边界

- UE5.8 Editor编译成功，源文件与预览工程SHA一致。
- 21项相关界面/指标测试及10项V4界面回归通过。包含阶段、旧场景/旧run拒绝、首帧与独立样本确认、后台动画停止、失败展示、方向键与原界面。
- 隔离小城实际启动与加载完成验证通过；50%密度实际生成300辆行驶车、300辆停放车、600名行人。车辆、行人的实际实体位置随时间变化；连续航拍转向/取图通过，所属进程全部退出，没有起飞。
- 约12秒相机扫视得到14个独立硬件样本：UE FPS中位数29.99、最低14.55，约11.46GB进程内存和4.47GiB显存。属于短时单机实测，没有做同缓存条件A/B基准，不能据此宣称消除所有停顿或整城稳定30FPS。
- 中间高密度测试曾请求超时，日志显示运行中临时创建头发与完整待机动画并出现约7秒包加载停顿。修正资产内的角色表示模板后，同类测试通过；最终运行仍记录到约1.75秒资源包处理，首次资源、纹理和地图流送仍会产生瞬时停顿。
- 光带仅300×8像素，80ms计时（约12.5Hz），采用不透明局部绘制，背景静态。短测基线CPU 0.078s/2s、显示时0.109s/3s、隐藏时0.094s/2s；隐藏时动画tick为0。未观察到可辨别额外CPU负担，但样本很短、计时粒度较粗，不作为精密性能基准。

证据：`docs/evidence/loading-population-20261105/`。加载预览和动画开销为独立GUI测试；loading-start-live、dense-report和dense-workbench来自实际隔离会话。大城市本轮未重新实测；算法训练、地面GT与机载红外未扩展。
