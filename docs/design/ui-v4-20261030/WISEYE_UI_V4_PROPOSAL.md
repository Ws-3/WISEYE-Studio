# WISEYE V4 界面分布与视觉方案

日期：2026-10-30。状态：**用户已批准，实施中，尚未逐项完成验收**。当前实际差距以 [复核表](../../UI_V4_GAP_REVIEW.md) 为准；本文件图片仍是示例，不代表完成状态。

本次交付是交互设计稿、10张页面效果图和实施规范。现有 PySide6 程序、UE、模型、红外成像、采样与保存逻辑均不改。设计以当前代码为基础，不能把效果图中的示例数值、假想路径或新增页面当成已有功能。

## 1. 改版结论

两端共用视觉体系，分别围绕自己的主要任务组织：

- 仿真端：搭场景、放设备、观察与控制、输出数据。默认进入仿真工作台。
- 训练端：接收同组图像和GT、检查目标、保存与校验数据。默认进入采集工作台。

保留两个独立窗口，通过右上入口互相打开；本轮不合并进一个进程。原有关闭保护与外部会话所有权不变。训练任务执行、模型评估、推理回传未来作为扩展，不能在这轮增加无后端的“训练中”仪表盘。

视觉沿用用户已确定的专业深灰、少量蓝色强调。通过布局、操作层次和反馈改善体验，不靠加发光边框或更大的标题。

## 2. 当前界面为什么不好用

| 当前代码表现 | 使用问题 | 改法 |
|---|---|---|
| 大标题、说明、卡片、选项占据多行 | 画面区域被不断挤压 | 固定紧凑应用头，说明移到字段旁、提示或帮助 |
| 左设备树、右标签页、控制对象选择同时出现 | 看哪个设备与控制哪个设备不够直观 | 分别显示所选属性对象、驾驶对象、云台控制对象、键盘输入归属 |
| 传感器参数嵌在右侧多层标签中 | 看画面与调参数相互打断 | 快捷参数保留，完整编辑使用有设备身份的右侧面板 |
| 场景编排以卡片、二维点图和坐标表为主 | 放在哪里需要切到UE判断 | 把观察画面与真实模型放置预览移到中央 |
| 训练端VIS/IR在上、融合在下占大面积 | 常看的两路原图被缩小，黑边与按钮很多 | 默认双路并排，融合缩略入口/按需展开 |
| 训练端连接、策略、目录、FPS全在左长表单 | 采集按钮和状态容易被滚走 | 连接放应用头，采集状态放顶部，设置按任务分组 |
| 多种FPS/响应时间看起来相近 | 容易把UE帧率当作保存速率 | 明确UE推进、普通新帧、GT组速率、落盘速率及请求返回耗时 |

上述分析依据 `workbench_v3.py`、`sensor_workspace.py`、`arrangement.py`、`secondary_pages.py`、`training_client/workbench.py` 等现有实现。

## 3. 视觉与尺寸规范

### 3.1 配色与字体

| 用途 | 建议值 |
|---|---|
| 主背景 | `#111418` |
| 面板 | `#191E25` |
| 浮起控件 | `#222A34` |
| 输入框 | `#13181E` |
| 分隔线 | `#303946`，1px |
| 正文 | `#E9EEF5` |
| 次级文字 | `#A2ADBD` |
| 主操作/选中 | `#5797FF`，限制在必要的小面积 |
| 正常/运行 | `#63C9A7`，同时配状态文字 |
| 待确认/警告 | `#E6B76C` |
| 错误/停止保存 | `#EC8390`，避免整屏红色 |

Windows优先 Microsoft YaHei UI / Segoe UI；正文13–14逻辑像素，常规说明12，页面标题18。设备ID、数值、地址使用Consolas等宽字体。原型截图部分辅助信息采用11–12px，正式实现关键状态不得压到11px以下。

按钮/输入框常规高度32–36，图标点击区至少28×28；间距以4/8/12/16/24为级差，面板内边距12–16，圆角6–8。只读数据不用与可编辑输入框相同的边框和背景。

### 3.2 屏幕与空间

以1920×1080、Windows100%为主要设计基准，同时验收1440×900、1366×768及125%/150%缩放。最小可用窗口建议1280×800；不足时折叠两侧栏，不能把所有内容整体等比缩小。

- 应用头：52–64逻辑像素，显示品牌、场景/任务、连接和打开另一端。
- 左导航：64–76，图标加短中文名称；不使用只有图标且无文字的导航。
- 页面工具栏：44–56，标题、布局切换和少量任务操作。
- 设备栏：200–230，可折叠；主要工作区剩余空间优先给画面。
- 属性/控制栏：288–320，可拖动调整；窄窗口转抽屉。
- 底部状态：26–32，只显示摘要和事件入口。

设计稿是布局参考，不要求逐像素复制浏览器尺寸。Qt需按逻辑像素、字体和可用高度重新计算；主要工作台不得整页滚动，复杂参数面板内部可滚动，固定保留底部应用操作。

## 4. 仿真端信息架构

导航建议为：**工作台 / 场景编排 / 设备管理 / 数据接口 / 资源设置**。

设备管理来自当前已有的管理弹窗，提升为稳定可返回的页面。航线编辑归属无人机任务，工作台可直接进入；环境与天气为全局参数面板，不与单传感器参数混放。

### 4.1 仿真工作台

默认三栏：设备树、画面工作区、上下文控制。

中央上方为场景观察大画面，下方VIS、IR和点云缩略条。上方紧凑显示“键盘：观察场景 / 驾驶：无人机01 / 云台：云台01”。一次只在一个地方编辑键盘归属，其他位置只回显。

画面顶部统一包含来源短码、名称、设备ID（按需）、状态、放大入口。分辨率/新帧率使用次级文字；录像红点只在实际保存已启动后显示。每个画面均支持适应、1:1、独立窗口、拖动换位。单击选中画面不夺取驾驶权。

布局提供三种预设：场景主导（默认）、双模态并排、多源网格。当前演示覆盖前两种，多源网格实施时复用已有最多四源的限制。布局只影响观看，不自动修改传感器采集启停或外部输出。

数据必须分清三层：

1. **画面显示**：是否放在本地工作区。移除画面不停止采集。
2. **设备采集**：传感器是否真的捕获/生成数据。停止会影响使用该源的其他订阅方。
3. **输出/保存**：RTSP发布或训练落盘任务是否运行。由相应服务管理。

菜单名称分别使用“移除画面”“停止此传感器采集”“停止发布/保存”，不共用含糊的“关闭”。全部受限于后端真实能力，不能为尚不支持独立启停的服务做假开关。

### 4.2 云台与无人机控制

右栏由所选设备类型决定，避免“无人机/云台/传感器”多层标签相互抢状态。

云台默认常驻：实例身份、当前实际模式、接管/停止并保持、目标、摇杆、实际角度、VIS/IR/雷达启停、编辑参数入口。UE真值跟踪必须保留“真值”字样，不包装成视觉算法跟踪。摇杆按住发送比例速度，松开/失焦/换控制对象清零，保留300ms看门狗。

无人机默认常驻：实例身份、实际飞行状态、起飞/悬停/降落、手动接管、航线摘要、位置/速度。真实旋翼RPM等展开查看；不再以普通醒目按钮诱导用户“播放旋翼动画”。状态来自实际飞控，不能因为按钮被点击就显示起飞成功。

无人机WASD、Q/E、R/F，云台方向键，以及观察相机输入分别限定在明确的输入模式中。编辑输入框时不触发驾驶；窗口失焦、动作切换和关闭时保持现有清零保护。

### 4.3 传感器参数

完整编辑从选中传感器或画面“参数”打开，标题固定显示设备名和device_id；VIS/IR/雷达是同一设备下的明确子页。

字段分组：常用成像 / 增益与噪声 / 安装与几何 / 接口与输出。前两项展开，低频高级项默认折叠。当前固定红外外观不恢复旧模式和两个旧预设。VIS/IR独立相机位置、视轴与基线继续保留，不能为美化合并成一个相机。

参数状态为：已应用 → 本地草稿 → 提交中 → 已确认，错误则保留草稿及原因。底部固定“恢复已应用值”“应用到此传感器”。等待期间不清空其他设备的草稿；晚回包按设备、会话、请求ID核对，不串对象。数字字段带单位、范围、步长与错误提示，非法值不得静默钳制或把旧值当新值成功。

采集开关属于即时操作，独立显示请求中状态；不能等用户提交成像参数时才意外启停。接口字段是否需重连/重启要明确提示。效果图示例字段不能直接照搬，实施前核对当前schema；无后端能力的字段隐藏或禁用并说明。

正式程序优先使用可停靠的侧面编辑器，允许观察画面继续刷新和控制栏保持可见。设计稿为强调层次使用遮罩；实际应区分可编辑面板与需要阻止操作的确认对话框，不能让遮罩挡住必要的安全停止入口。

### 4.4 场景编排

不再把二维点图当作主要画面：左设备列表与预设，中央UE观察/放置预览，右位置姿态，底部明确当前草稿与应用状态。二维XY示意仍可作为辅助折叠视图，不能伪装成真实地图。

流程为：选择实例 → 聚焦或自由观察 → 到UE预览放置 → 查看完整等尺寸半透明模型 → 锁定/微调 → 确认并应用 → 需要时保存初始布置。

保留现有WASD/QE/RF、Shift精调、按住连续微调、贴合表面与物理约束。画面中显示设备名、位置和表面偏移，但不能遮住模型脚点。原型中使用位置标记演示，正式实现必须复用现有完整模型预览，不能退回只有一个点或标签。

“确认并应用”改变当前场景位置；“保存初始布置”保留下次启动；“加载场景”用于换地图、增删设备/换型号等现有需要重载的情形。不要恢复每次坐标变化都要求重新加载的旧逻辑。无人机空中不能移动初始物理位姿。

中央复用现有OBS画面/预览链路。本轮不承诺直接嵌入完整UE编辑器；在系统画面里直接点击射线取点/操纵器属于需另外验证坐标、DPI与镜头时序的新功能，未验收前保留“到UE操作”。

### 4.5 航线任务

从驾驶栏打开较大的独立任务视图：左/中预览，右航点列表、所选航点参数与任务状态。航点表列出顺序、XYZ、速度、停留，支持增删、重排和逐行校验。

状态明确区分本地草稿、已上传、执行中、暂停、完成、错误。编辑后标记“需重新上传”；执行按钮需要正确无人机已起飞且任务已确认。上传不等于执行，保存不等于起飞。

第一阶段保留现有坐标编辑/上传/执行。真实UE航线线条、拖动航点、碰撞/地形检查为P2新增，效果图虚线不代表已实现自动避障；不为截图额外采集新的场景相机。

### 4.6 设备、接口与设置

设备管理用实例表＋单设备详情，支持现有新增、编辑、复制、删除流程。显示名可改，device_id稳定；复制产生新ID。默认场景仍一架无人机一套云台，不因效果图自动添加设备。

数据接口页优先显示来源、规格、采集/发布状态、实际地址、复制、测试/详情。RTSP、GT数据、云台控制和飞控分组；未知或未启动明确显示未可用，不能共用一个绿色“正常”。地址从当前配置生成，禁止硬编码效果图中的示例URL。

资源设置使用左侧短分组、右侧表单：连接与会话、性能画质、存储工作区、窗口布局、资源版本。高风险的重载/重连/删除说明其影响，普通布局修改不弹多余确认。地图仍使用当前City Sample，不为效果图更换或下载资产。

## 5. 训练端布局与交互

### 5.1 主界面

默认双路并排，VIS和IR获得主要空间，保持16:9和5:4原始比例，不拉伸；可以一键将IR作为主画面，VIS缩略。对远距小目标，原图1:1、滚轮缩放、独立放大窗口比盲目提高显示分辨率更重要。

融合默认是下方小入口和状态摘要，点击后展开为大面板或独立窗口；需要持续对比的用户可将三路布局保存为偏好。必须保留raw/rotation几何语义：原始叠加仅统一FOV尺度，旋转补偿不消除双光心的深度视差，不能写成“已完全配准”。

连接设置从左侧长表单移到应用头。采集状态条始终可见：连接来源、当前模态、实际预览/请求上限、实际保存/保存上限、已保存组数、开始/停止保存。常用采样和目录在右栏，策略高级项在采集设置内展开。

### 5.2 三种状态不能混淆

| 状态 | 应显示什么 | 操作影响 |
|---|---|---|
| 连接 | 未连接、连接中、已连接、重连中、错误 | 控制数据通道 |
| 采集 | 当前会话/设备/模态、请求与实测速率、有效样本状态 | 控制同组图像与GT接收 |
| 保存 | 未启动、写入中、正在停止、失败；已写组数 | 只控制落盘，不擅自断开预览 |

保留当前统一图像+GT来源，不恢复旧视频/样本模式；默认预览上限5、保存1是当前设置，不以UI改版宣称30FPS。GT显示开关仅切换叠框，隐藏GT仍保留、校验并保存标签。配对身份和同刻约束保留，不用旧GT叠新帧。

断连/换源/变更策略时清除不匹配图像和缓存，放大窗口跟随清屏。数据恢复后只能显示新会话的有效组。模态改单路时禁用配对融合并说明，至少保留一路；订阅切换不是仿真传感器供电开关，不能默默影响仿真端其他使用者。

在线目录、策略、源变更继续使用现有版本快照和异步切换。数据会固定追加到所选根目录下visible/IR，不增加samples或pairs层。记录是否生效、从哪一组生效；磁盘空间/写入失败独立报错，停止失败保存任务并保留查看能力。

### 5.3 FPS与延迟

UI必须明确：UE推进FPS、普通预览新帧Hz、带GT有效组/s、落盘组/s。GT配对按组计数，不能把两张图合计成两倍FPS。请求上限与实测值分开显示，重复图像不算新帧。

采集时差为两路仿真时间差，请求返回耗时为本地往返，均不等于完整端到端延迟。单向传感器年龄无法可靠测量时显示未知；两电脑未时钟同步前不直接相减绝对时钟。UI改版不应承诺改善GPU读回或真实采集上限。

### 5.4 样本检查：建议新增，但单独审批实施

当前主程序没有完整样本浏览器。建议P2新增只读样本检查：左数据集/筛选，中缩略图，右配对身份、型号、天气、标注状态和详情。

以JSON的会话、设备、模态和样本身份匹配数据，检查图像/标签/元数据完整性；有效空标签才是负样本，文件丢失或标注失败不能算负样本。首期不删除、不自动改标签、不重写用户既有目录。不得按文件排序把VIS/IR错误配对。

效果图多张缩略图重复使用一张真实样本，仅表示布局；示例统计不是对用户数据集的分析结果。

## 6. 公共状态与异常

统一覆盖：未连接、启动中、空数据、禁用源、缓存过期、能力不支持、断连重试、参数草稿/提交/失败、保存失败、退出中。每个状态给出一条可执行操作，避免只有“读取失败”。

危险操作与日常操作区别：删除设备/丢弃未应用草稿需按现有规则确认；暂停、停止输入和悬停应易于找到，不能藏在更多菜单。关闭主窗口延续现有受管退出流程，不能为了动画把窗口直接销毁。

事件日志默认收起，底部显示最新一条和错误数，点击展开；同一反复错误合并计数。错误给设备身份、通道和可复制详情，不把后台命令栈堆满主工作台。

未知硬件指标显示“不可用”，真实低性能提示基于已有持续多样本规则。硬件只用一行摘要/紧凑分组，不在大画面上常驻四五个监控卡片。

## 10. 验收清单

1. 1920×1080与1440×900主工作台无需整页滚动；125%/150%DPI下主操作可见。
2. 画面始终保留来源身份与原始宽高比；缩放不改变源分辨率、FOV或训练标签。
3. 单击设备/画面不改变驾驶/云台控制；接管后有明确持续指示。
4. 输入框中打字不触发飞行；换模式、松键、失焦、关闭清零。
5. 多设备参数、取点和回包不会串设备，晚到回包不能清掉新草稿。
6. 不支持/禁用/预热/断连/过期各有状态，放大窗口同步清理。
7. 布局/放大只复用已有源，不因多开一个窗口再建一套采集或解码器。
8. 动画、阴影、日志刷新有限频，不能新增完整场景捕获来实现装饰效果。
9. 训练同刻包、GT有效性、正负样本规则、visible/IR追加目录不变。
10. 点击停止保存只停止落盘；保存失败明确提示，不继续显示“保存中”。
11. 起飞、降落、云台跟踪/保持、在线放置、航线上传与执行实际联调。
12. 关闭保护回归：主窗空中退出、直接关UE、关闭所属训练、保留外部UE。

性能验收使用同一场景、相同源数量与分辨率对照：记录GUI线程处理时间、显示新帧率、样本接收/保存组速率、内存与队列长度；改版不能用更低采样率掩盖性能退步。没有GPU余量测量前，不承诺30FPS。
