# 网络与传感器接口（2026-10-26）

进入「数据与接口」→「编辑网络与传感器接口」，或数据源行的「操作」→「编辑接口」。设置页也有入口。

- RTSP 服务主机、端口、可见光/红外/观察流路径、发布帧率及网关 JPEG 质量可以保存。
- 每台 ptz-01～04 的 visible/infrared 可勾选独立路径覆盖；取消勾选后恢复跟随默认规则。新增云台自动使用 `ptz-02/CH1` 等默认路径，网关与界面共用解析器。
- 主机填写 IPv4 或主机名，不含 `rtsp://`；路径填写如 `camera2/thermal`。不同源不能重名，禁止空格、`..`、首尾斜杠。
- 本机 RTSP 主机为 `127.0.0.1` 或 `localhost` 时，启动器按新端口生成可写 MediaMTX 配置；填写远程主机时，向用户已部署的远程 RTSP 服务发布，不代为安装远程服务器。远端需允许发布，当前界面不支持鉴权凭据、IPv6或RTSPS。
- UE 控制、云台控制、原尺寸 JPEG 预览、点云共用 UE JSON Lines 通道；点云方法 `sensor.lidar.get_points` 和 device_id 是协议定义，不存在独立 RTSP 点云流。端点编辑与采集参数编辑分开，采集参数仍在各传感器属性页独立设置。
- UE 主机、UE 端口和飞控连接端口可保存，适用于连接已部署的服务。内置 UE/飞控监听端口仍为 50051/50052；本机独立启动会校验这一约束，不会假装修改服务器监听端口。

先降落并退出仿真，断开 UE/飞控连接，再保存。修改发布设置后重启 RTSP 服务；独立版下次启动仿真会自动使用新值。开发版先退出自己启动的旧 MediaMTX/网关，再运行 `scripts/Start-RTSP.ps1`，不要同时保留旧服务。配置保存是原子替换，验证失败不覆盖原文件。

独立版配置在 `%LOCALAPPDATA%\WISEYE\configs\app.json`，开发源码版在项目 `configs/app.json`。旧配置不用迁移，新字段都有默认值。RTSP 主机现在是显式配置；跨机器部署请将它改成实际视频服务地址。

桌面实时画面继续直连 UE 最新帧，编辑 RTSP 不会将桌面改为 H.264 解码往返。

验证：51 核心测试、11 Qt 回归通过；本地 MediaMTX+FFmpeg 使用自定义端口 19554、路径 `custom/camera2/thermal` 发布并解码3帧640×512测试信号通过。后者是合成信号的传输验证，不是新一轮真实UE红外或RTSP延迟验收。
