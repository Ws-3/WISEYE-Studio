# 当前红外版本与局部热区（2026-10-29）

保留用户认可的楼宇灰度/对比基础，只更新轮廓柔化、目标热区及入口整理。源码F，本机构建E；旧独立包未重新打包。

## 界面与建筑轮廓

传感器页不再提供楼宇/材料/参考/增强/原始等成像版本选择，删除“清晰观察”“实拍近似·未标定”两套预设及其数据。当前只用本版红外，保留白热/黑热、FOV、噪声、模糊、增益等真正的参数。底层旧协议和历史材质文件用于兼容与历史回放，不再作为界面中的可选效果；本版材质生成仍复用内部着色器模块。

在最终灰度显示后增加轻量光学低通，减轻高对比曲线放大的细线和轮廓过硬感。目标像素和紧邻目标的像素被保护，不把微小无人机热量平滑到背景。原始信号、目标掩码、GT、已接受的楼宇基础灰度曲线不改写。

## 电机与电池

原局部电机投影只接了Avata；现Mavic也使用四个实际旋翼轴心的世界位置，投影到实际红外相机。Mavic电机热区半径1.6cm、电池4cm，Avata电机1.5cm、电池3cm；最低亚像素投影用于采样，不额外扩大远处目标尺寸。电池参考点按机身局部后向位置偏置，属于工程近似，不是CAD内部电池测量。

局部热强度随真实RPM推导的功率、Motor/Battery热状态变化：电机较快升温、电池较慢，降落后继续冷却。Gaussian热区仅叠加到可见目标及近深度范围，避免画到前景建筑；对机身内部自遮挡仍是近似深度门限，不是各零件物理辐射计算。归一化热信号不是摄氏温度。

还修复了窄视场对天空时的高光问题：背景AGC窗口较窄，原显示会把整个无人机一起压到相近高亮。现在目标显示结合原始归一化热信号的平滑映射，保留电机/电池局部差别，再做白热/黑热反转，避免只增加热参数却依旧显示单色块。

## 为什么训练端只有1–2 FPS

- 界面默认显示1 FPS、保存1 FPS，用户可以分别设到2 FPS。
- UE的`camera.sample_request`和`camera.sample_pair_request`按每个设备/传感器设置0.5秒最短间隔；多个采集者共享该限流。
- 这里每组是同Tick双路图像、各自深度和可见性/遮挡GT、编码与网络返回，并非普通视频播放。显示和保存独立限频，不补重复帧。训练端的统计也不代表UE世界Tick FPS。
- 原预览被检查时处于暂停，降落等待未完成且飞控曾报连接超时；本轮正式测试使用正常推进的隔离仿真。暂停时不要用没有运动的新帧判断运动延迟。

此次没有直接调高GT采样上限。真正的提速路线是：快速视频预览复用最新JPEG缓存；带GT的同步样本按独立频率采集和保存。快速预览应显示采集时间和“无同步GT”状态，不能把旧标注贴到最新视频上。进一步提速同步GT需要单独测量并优化深度读回、可见性计算、编码与调度，再确定可靠帧率；重新打包UE不会自动解决这个限流。

使用：正常启动系统，云台→传感器→红外调整参数。近距离检查电机/电池时收窄FOV；640×512下远处小目标的热区会因采样和光学模糊融合，不能承诺始终看见四个独立亮点。
