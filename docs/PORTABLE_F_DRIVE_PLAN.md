# F 盘便携运行评估

> 最新需求澄清（2026-10-22）：用户将移动硬盘主要作为传输介质，后续也通过下载获取。当前首选方案改为本地 SSD 安装运行，详见 [PACKAGING_AND_UPDATES_PLAN.md](PACKAGING_AND_UPDATES_PLAN.md)。下文盘内 Data、直接从移动盘运行和便携更新均为可选扩展，不再是首版交付要求。F 卷问题不阻塞本机打包或网络分发。

日期：2026-10-22。结论：容量与介质类型适合承载 WISEYE 便携版；F 盘当前文件系统状态需要先处理，尚不能判定已具备可靠的正式运行条件。本轮未修复磁盘、未格式化、未向 F 盘写入或部署程序，也未进行性能压测。

证据：[portable_f_drive_assessment_20261022.json](evidence/portable_f_drive_assessment_20261022.json)。物理盘 Healthy 与卷 Warning 属于不同层次；Dirty 标记意味着文件系统可能不一致，不直接证明 SSD 硬件损坏。先备份盘内重要文件，再使用 Windows 磁盘检查流程处理卷问题，复查状态后再部署正式包；不能直接清除标记来代替修复。当前未操作这些文件系统变更。

按上一方案全套 25–60 GiB 的早期安装容量预算，剩余空间足够；仍需首个 Cook 后实测包体。便携版初期建议保留至少 120–150 GiB 空闲作为完整城市更新、旧版回滚和临时下载预算，实际由更新器按变更量计算。剩余 606 GiB 不能等同全部可用于连续录制，现有盘内其他数据也要保留。

## 便携运行方式

将 F 盘用作发布介质和运行位置。保持开发源码、编译、Cook 与暂存目录在本机 E 盘；完成构建后才把独立发布包复制到移动盘，不将源 CitySample 104.7 GiB 和完整 UE 编辑器一起复制。

```text
F:\WISEYE-Portable\
  WISEYE.exe                  # 双击启动
  portable.json               # 便携模式标识及相对路径
  versions\<release-id>\      # 桌面、UE Game、飞控/视频进程及运行库
  content\<content-id>\       # 基础/城市 Cooked 资源
  Data\                      # 随盘携带的设备、航线、布局、参数
  Recordings\                 # 用户选择在盘内保存的录制
  Updates\                    # 更新暂存与断点下载
  Prerequisites\              # 必要时使用的运行库安装程序
```

启动器以自身位置定位资源，不写死 F:、E:\Projects 或开发电脑用户目录。因此插到另一台电脑变成 G: 或 H: 也应能运行。上述为拟议发布结构，目前尚未生成。

便携版覆盖通用安装方案的默认用户数据路径：设备、航线和布局默认放盘内 Data，便于跨电脑延续；显卡驱动缓存、可再生缓存及机器相关诊断优先放该电脑 `%LOCALAPPDATA%\WISEYE\Cache\`，按构建及机器环境隔离。不要把另一台电脑的 GPU 缓存当作可通用资源。普通运行不必把几十 GiB 城市复制到 C 盘，但会产生少量本机缓存和必要系统运行库。

配置中引用用户文件时优先使用便携根相对路径；盘外文件保留原路径并在换机缺失时明确提示。跨电脑需验证 NTFS 读写权限，遇到不可写状态应提示选择可写数据位置，不能默默丢失保存。盘内所有 worker 和工具均须完整自带，不依赖本机 `.venv`、Anaconda、源码目录联接或 PATH 中的 FFmpeg。

## “插到别处直接用”的条件

首版以 Windows 11 x64 为支持目标，其他操作系统不作即插即用承诺。对方电脑不需要 UE 编辑器、VS、Git、Python，但需要适合当前 UE/Nanite 的显卡、驱动和系统功能。缺 VC++ 等必要运行组件时，首次启动给出明确检查结果，必要安装可能需要管理员权限；GPU 驱动不能靠复制移动盘替代。

当前城市高负载，普通办公电脑不能保证顺畅运行。32 GiB 内存可作为测试起点，64 GiB 更适合城市；显存、图形功能和实际帧率需针对目标机器验证。官方 CitySample 推荐 SSD，Nanite/虚拟阴影依赖较快读取；移动 SSD 的最终表现仍受硬盘盒、USB 端口、线缆、供电及持续负载影响。

优先直接连接高速 USB 端口，避免低速集线器。本机只确认 USB 总线，没有确认实际协商速率，不能以 Ti600 的内部 NVMe 标称速度当作移动硬盘的实测速率。

## 性能与在线更新

移动盘不会让包体变小，其价值是携带方便、减少其他电脑内置盘占用。冷启动、城市流式加载可能慢于本机 NVMe；画面编码/显示延迟、GPU 性能和仿真负载仍需独立优化。普通录制可以放移动盘，同时高频写录制和读城市产生负载时可改用本机 SSD，再按用户选择导出回盘。

便携更新沿用签名版本清单、完整性校验、组件兼容组合和回滚设计，更新落在便携根内，不依赖这台电脑的卸载注册信息。界面变更复用未变城市。运行时可后台下载，但退出仿真及相关进程后才在同一 F 卷内切换版本。

从 E 盘复制到 F 盘不是原子切换：先复制到 F 盘的新暂存目录，校验全部发布文件，再在 F 卷内激活。更新中断或断开连接不能使半包被当成有效版本；旧版保留直到新版本通过启动检查。应用及其子进程全部退出并完成写入后再安全弹出移动盘，不能运行中直接拔盘。

## 实施与验收顺序

1. 处理 F 盘当前卷问题并复查；保留已有目录和数据，不格式化、不整体迁移工程。
2. E 盘构建基础独立包，再生成城市包，去除对编辑器及开发机路径的依赖。
3. 生成便携版的数据根、相对路径、worker 启动和依赖检查；复制、校验后放入独立的 `WISEYE-Portable` 目录，不覆盖盘内其他项目。
4. 本机从 F 盘冷启动，测加载时间、实际读延迟、卡顿和连续城市飞行；并比较 E 盘同一发布包，不能只测顺序读取速度就判定仿真流畅。
5. 换一台没有 UE/Python/Anaconda 的 Windows 电脑，验证变盘符、普通用户、配置随盘保存、不同显卡冷缓存和离线启动。现有两台开发机不足以证明完全脱离开发依赖。
6. 验证便携版在线更新、下载中断恢复、坏包拒绝、失败回滚和安全退出弹出；断盘故障测试使用可恢复测试副本，不在用户现有重要数据上制造异常。

下一里程碑仍是生成第一个真正的独立运行包，不是复制当前开发工程。F 盘方案不要求同时先实现 GPU 共享显示，可在同一发布架构下分步推进。
