# 红外探测器处理第一批（2026-10-28）

本批完成可复现对照（P0）及云层空间滤波、增益控制（P1）。它是在现有热信号代理上改善显示的工程试验，不是摄氏温度、LWIR 辐射模型或 Anti-UAV 相机标定。

## 使用

运行源码预览入口 `scripts/Start-SimulationPreview.ps1`，选择云台 → 传感器 → 红外。

- 点击“清晰观察”或“实拍近似 · 未标定”，再点击“应用更改”。预设只填草稿，保留当前视场，不启动其他设备或修改地图。推荐先用 1×；2×增加 GPU/读回开销。
- 成像模式用“楼宇热像 · 试验版”。“云层去颗粒”0–1，仅处理天空掩码内像素；建议 0.4–0.8。它不会去掉全部云采样噪声。
- 增益“自动”可勾选“稳定自动增益”，以背景统计、死区和限速缓解亮度跳变。建议切换视角后等待适应；不是瞬时恢复。
- “锁定当前范围”保持当前实际增益窗口，转动云台及红外停止/重启后仍保持。初次采集尚无窗口时锁定的是初始 0–1；应先自动适应再锁定。
- “手动信号范围”使用归一化上下限，均在 0–1，间隔至少 0.01；不是温度。显示亮度 -0.3–0.3。实际生效栏显示当前 AGC 窗口。
- 噪声种子 0–2147483647。种子与帧序号共同决定合成探测器噪声；固定种子不能固定 UE 云采样、视角运动或完整仿真。

新能力 `detector_controls_available` 不存在时，界面不向旧 UE 提交新字段。参数按云台隔离，仅本次运行有效；旧五种成像模式及默认 reference 保留。稳定增益和手动窗口用于 reference/classified/facade 读出，天空滤波只用于 facade。旧自动增益字段与新模式不能矛盾。

## 实现顺序与目标保护

FP16 代理信号 → 1×或2×下采样 → 天空空间滤波 → 原光学 PSF → 探测器噪声 → 自动/锁定/手动增益 → 对比、亮度、极性和高亮压缩 → UE 显示纹理及 JPEG。

滤波使用两次三点边缘权重处理，无跨帧历史，因此不引入时域拖影。非天空中心、目标掩码不参加天空平均；2×下任意子像素命中目标即保护，只有四个子像素全是天空才滤波。光学 PSF 仍会正常影响目标，不能理解为小目标在最终图像中绝对不变。原生测试验证 2×2 目标在天空滤波阶段数值不变及混合子像素保护。实际飞行验证用于防回归，尚未完成远距离 1–3 像素目标的检测率评价。

稳定 AGC 采用 0.5%/99.5%背景分位数、最小窗口 0.20、0.003死区及每秒0.15信号的边界限速；有效背景不足20%时回退全帧。它改善适应稳定性，仍可能在大角度切换后缓慢改变亮度。

UE 体积云自身随机采样导致两次实时截图不可直接归因于滤波。本次保留同一帧滤波前的归一化 float32 信号及天空/目标掩码，由与运行时共享的 C++ 数学代码回放。回放文件不是原始测温数据。噪声置0、手动范围0.05–0.45、PSF0.8、对比1.1，相同输入只改变天空滤波0→0.8。

## 回放 / 重新验收

用 VS 2022 x64 C++17 编译 `tests/native/replay_thermal.cpp`，生成到构建目录，不向仓库添加 exe。

```text
replay_thermal.exe cloud.f32 cloud.sky.u8 cloud.target.u8 baseline.pgm 0
replay_thermal.exe cloud.f32 cloud.sky.u8 cloud.target.u8 smooth.pgm 0.8
python -m tests.verify_infrared_detector_live --replay E:/Projects/WISEYE-IR-Work/replay_thermal.exe --output E:/Projects/WISEYE-IR-Work/new-detector-check
```

离线回放输出为未经过 JPEG 的 PGM，不与另一帧 JPEG 像素强行比较。默认不录原始信号，诊断 API 必须显式启用；其内存与Base64传输有额外开销，不作为实时预览通道。

本批没有重打独立运行包、推送 GitHub、整城重设温度或安装插件。20261027旧ZIP不含本批功能。后续优先：选真实相机视频作统计基准、远距小目标对比度/PSF/运动校准、独立云辐射信号与夜间背景，最后再做长期延迟及Cook验收。
