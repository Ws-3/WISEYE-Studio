# 运行状态与环境控制（2026-10-27）

## 入口

源码试验版的仿真工作台上方新增硬件状态栏，右侧「环境与天气」打开全场景环境控制。使用已更新的内置构建与桌面源码：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\WISEYE-Studio\scripts\Start-SimulationPreview.ps1"
```

等待加载后连接UE。此入口复用原红外预览的隔离配置与进程管理，也包含本次性能与天气功能；旧完整发布包和20261026桌面接口更新ZIP没有本次C++改动。当前尚未重新Cook/发布，不能仅替换Python界面就要求旧UE支持新接口。

启动命令只为这次PowerShell进程指定执行策略，不修改全局策略。Windows PowerShell 5.1读取无BOM中文JSON必须显式指定UTF-8；启动脚本已修复并用5.1验证场景中文读取和三项进程启动参数生成（测试中模拟进程启动，不额外启动UE）。

## 硬件状态

统计来自**仿真运行主机**，连接远程UE时不会误显示桌面电脑的硬件。UE每秒采样，桌面随正常状态轮询显示：

- CPU型号（悬停详情）与系统CPU占用、系统内存已用/总量、UE进程内存。
- UE实际选用的显卡名称、驱动报告的专用显存总量。
- UE本进程的本地显存使用量和Windows/驱动给本进程的预算。预算不是物理总容量，不能把“预算使用率”写成“整卡显存占用率”。集成显卡/不支持的驱动可能无法提供部分字段。
- UE GPU引擎峰值：Windows PDH对本UE进程最忙引擎的读数，不是整卡总GPU百分比。用英文计数器API兼容本地化Windows，不弹命令行，不依赖nvidia-smi。驱动没有计数器时显示“未提供”。
- UE实测帧率：墙钟时间内实际Tick数，不拿画质档位的帧率上限或桌面视频帧率冒充。

连续三个不同采样出现以下情况时，在状态栏给出非弹窗提示：UE显存使用达到驱动预算90%、系统内存达到90%、UE帧率低于20。短暂低值或同一个采样重复到达不累计。恢复后清除提示，断开时清空旧数值。不根据显卡品牌直接认定机器性能差，也不自动改变画质或停止飞行。加载时的低帧率提示应在加载完成后再判断。

## 环境控制

- 时间：勾选「使用指定时间的光照」，选择00:00～23:59，点击「应用环境」。调整太阳方向、强度和天空光强度；关闭勾选恢复原始场景光照。当前是固定太阳路径的视觉模型，不是按经纬度/日期计算的天文模型，不依赖场景必须带SunSky。
- 雾：0～100%，叠加到场景原有指数高度雾基线，必要时只在运行时创建雾Actor。它是强度控制，不是经过标定的米制能见度。
- 雨：0～100%，复用项目已有ProjectAirSim天气粒子，在各云台和观察相机附近布置随视角移动的雨效体积。缺资源时禁用，不用滑块假装已经下雨。城市地面湿润、积水、降雨对飞行器的作用力和红外大气衰减尚未自动联动。
- 「晴朗」「大雾」「下雨」只填写草稿，仍需点击应用。所有云台共享环境；传感器自身参数继续按设备独立设置。
- 「恢复场景默认」恢复本次加载时的太阳、天空光、雾与雨参数，并销毁此接口创建的临时雾/雨体积。不保存关卡，不覆盖用户Fleet/航线。环境设置仅本次运行有效。
- 提交时锁定字段并按请求ID确认；断连或能力缺失时不可提交。旧UE无接口时必须升级仿真，界面不会把草稿当成已生效。

环境改变首先作用于可见光和UE观察画面；红外试验仍是近似热成像，尚未加入随昼夜变化的表面温度、雨雾的物理红外透过率。夜间效果受场景已有天空和自发光材质影响，不能声称是真实照度/温度标定。

## 扩展接口

继续使用现有UE TCP/JSON Lines协议，`sim.get_state` 新增 `runtime_hardware` 和 `environment`。两者均指运行主机/全场景，不属于某一云台。

```json
{"version":1,"request_id":"env-1","command":"environment.configure","payload":{"time_override":true,"hour":18.5,"fog":0.3,"rain":0.7}}
```

`environment.reset` 的payload为空对象。配置要求hour在[0,24)，fog/rain在[0,1]且全部为有限数值；校验失败不改设置。响应仍是完整状态，`environment` 包含能力、设置值和雨体积数量。回读确认的是已应用的运行参数；GPU图像缓存需等待几个新帧才反映改变。

性能字段缺失表示未知，不是0。硬件采样没有额外视频读回、子进程或GPU渲染查询等待；Windows CPU/PDH与RHI缓存统计每秒读取一次。大雾、降雨和动态光照本身可能增加渲染开销，可结合状态栏选择节能档和减少启用的传感器。

## 本轮验收

UE5.8.4 Editor Development构建、53项核心测试与15项Qt回归通过。真实Small City的时间/雾/雨参数与图像已验证，非法参数拒绝且不改变状态，测试结束恢复运行参数并退出测试游戏。原用户city Fleet保持不变；没有在本轮起飞、重做长期/4+4或打包Shipping。

本机真实读到Intel i5-14600KF与Intel Arc B580。一次城市采样中UE约使用4.23GiB本地显存、预算11.08GiB，实测约30FPS；数字是该次采样，不是固定资源需求。雨效画面可见滴落/折射，雾降低远景对比。夜空仍受原始天空材质与曝光影响，降雨不自动修改城市地面材质。动态光照时日志有经济档虚拟阴影页池溢出警告，阴影预算优化仍待专门评估，不以扩大显存预算掩盖问题。
