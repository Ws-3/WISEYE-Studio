# WISEYE 仿真平台系统设计方案 V2（已批准，分阶段实施）

日期：2026-10-19。状态：用户已明确批准按方案实施；默认场景主导，先实施 A 与性能基线。以下方案定义完整目标，实际完成状态以 AI_HANDOFF 和项目计划为准。

## 1. 建议审批的方向

WISEYE Studio 定位为“无人机与光电设备仿真平台”：配置环境、布置设备、运行飞行、模拟传感器、查看与记录原始数据、提供稳定数据/控制接口。检测、识别、跟踪算法、融合、重建和评估在独立扩展应用完成。

保留 UE 5.8.3 + Project AirSim + PySide6；采用分阶段改造，复用已有传感器与协议。先完善单架流程和观测操作，再优化数据面，再增加多架。数据模型从第一阶段就使用设备 ID，避免日后推倒重来。

推荐默认布局为“场景主导”：左侧设备树、中间场景与传感器、右侧所选对象属性、底部运行事件。另提供“传感器主导”布局，用于主要观察双模态与点云的工作。布局只改变工作区，不改变实际传感器或飞行控制权。

## 2. 当前事实与缺口

以下来自本机源码与已有验收记录，性能数字为此前实测，本轮没有重新跑性能测试。

| 项目 | 当前情况 | 设计缺口 |
|---|---|---|
| 场景 | original/test_range、多地图注册与安装 | 缺少可视化放置、保存初始布局与直观重置 |
| 无人机 | 一个 Drone1 动力学对象；Mavic/Avata 是其外观选择 | 切机型不等于创建第二架；多架需要真正独立状态和动力学实例 |
| 飞行 | 手动/固定自动航线、起飞/悬停/降落 | 操作分散；缺航线编辑、控制权标识及完整就绪流程 |
| 观察视角 | 总览/云台/无人机跟随三个预置 | 缺独立自由观察相机、对象聚焦与清楚的输入焦点 |
| 可见光/红外 | 1920×1080 / 640×512，双 RTSP 输出 | 查看通道、工作传感器、参数控制容易混淆 |
| 点云 | 三维/正视/俯视；48×12，30°×8°，10 Hz | 当前单帧有限采样；缺统一时间戳、参数面板和二进制订阅 |
| 视频 | 异步 readback → JPEG/Base64 → Python → libx264 → RTSP → FFmpeg 解码 → QImage | 多次复制和编解码，尚非 GPU 直通；当前 GOP=1 |
| 帧率 | 历史输出 CH1 30 FPS / CH2 25 FPS；同时约 20 FPS 独立新渲染帧 | 重复缓存帧不能作为真正采集帧率；端到端延迟尚未完整测量 |
| 桌面视频 | 一次显示一路，固定解码适配为 960×540 | 保持比例但缺原生像素查看、并排对比及每路负载管理 |
| 接口 | UE 50051、AirSim runner 50052、RTSP 8554 | 缺对象寻址、订阅发现、统一时钟与命令生命周期 |

## 3. 系统职责边界

| 仿真平台负责 | 扩展应用负责 |
|---|---|
| 场景/环境与设备布置、飞行与云台控制 | 目标检测、识别、视觉跟踪与融合 |
| 原始 RGB、合成红外、激光回波及设备状态 | 点云重建、地图构建、分析可视化 |
| 参数校验、实际生效反馈、坐标与时间定义 | 模型训练、权重管理、算法性能评估 |
| 标准视频/二进制/遥测接口与接口示例 | 算法叠加界面、算法结果报告 |
| 原始采集会话、参数快照、事件记录及导出 | 复杂数据清洗、标注、科学分析回放 |

平台保留 UE 真值指向功能，明确标为“真值跟踪”；它是仿真辅助能力。扩展应用未来可经控制接口请求云台角度，但必须申请该设备的控制权。平台不因此内置算法运行页。

原始录制属于数据出口的一部分。平台负责数据可追溯和基础会话管理；复杂多模态分析回放可由独立应用建设。

## 4. 页面与工作流程

主导航只保留四项：

1. **场景编排**：地图选择、设备/无人机列表、初始位置和姿态、初始传感器参数、航线、环境预设、保存布局。
2. **仿真工作台**：运行/结束、独立观察视角、传感器面板、选中设备操作、手动/航线控制。
3. **数据与接口**：可用数据源、地址/格式/时间/状态、复制连接信息、原始录制开关与会话列表。
4. **资源与设置**：场景/机型/传感器预设、运行环境检查、显示质量、连接和性能诊断；日常不常驻大量技术参数。

推荐流程：打开或新建场景预设 → 布置对象 → 保存初始状态 → 校验 → 进入就绪 → 选择起飞对象 → 起飞/悬停 → 手动或执行航线 → 可选记录 → 悬停/降落 → 结束会话。

默认加载场景后保持就绪，不自动起飞或执行航线。必要操作集中在当前任务位置；地址、端口和服务日志收进“连接详情”，不占据工作区主位置。

全局运行状态和每架无人机的飞行状态分开。全局采用“未连接/编排/校验中/就绪/运行/结束中/故障”；每机采用“未解锁/起飞中/悬停/手动/航线/降落中/已降落/失联”。

## 5. 工作台布局

- **顶部运行栏**：场景预设、会话、启动/结束、记录状态、总体告警；显示当前控制对象与输入模式。
- **左侧对象树**：环境、地面设备、无人机、传感器、航线；对象有固定 ID、可改显示名和独立状态。选择对象只改变属性面板。
- **中央工作区**：场景观察、传感器单画面/双画面/四宫格；允许调整比例、最大化、弹出窗口。选“场景主导”时场景为主画面，传感器是侧边小窗；选“传感器主导”时可见光/红外为主，保留场景小窗。
- **右侧属性与操作**：只显示当前对象相关的参数与动作；常用项在前，高级项折叠。顶部始终显示对象名称、类型和 ID。
- **底部状态区**：简洁事件与告警，可折叠；详细服务日志在诊断页。

“选中对象”“正在手动控制的无人机”“云台跟踪目标”“查看的数据源”分别显示，分别赋值，避免点击一张画面意外改变其他控制。

布局可以保存为个人工作区；设备位置和任务参数保存为场景预设；运行日志和采集数据保存为会话。这三种持久化互不混用。

## 6. 传感器画面与参数

### 显示

每个画面以 sensor_id 绑定到设备，例如“PTZ-01 / 可见光”。同时显示源分辨率、有效新帧率、画面时间/是否过期；延迟仅在已正确测量时显示数值，不能用接收帧率代替延迟。

支持适应窗口、1:1 像素、局部放大、并排观察和快照。显示缩放不改变源分辨率，显示通道切换不关闭其他正在输出的数据流。双模态对比需要明确各自帧时间，不能把相邻帧冒充同步帧。

传感器工作状态改为各传感器独立“启用采集/启用输出”；“查看哪一路”只属于布局。地面同一云台的可见光、红外、激光可同时工作，硬件联动限制放进设备配置。

断流时可保留最后一帧，但覆盖“已过期”和最后更新时间；零激光回波是合法数据，与断连分别显示。图像中的十字线、包围框等叠加可关，原始输出默认不混入 UI 字样。

### 参数分组

| 对象 | 常用参数 | 高级参数与限制 |
|---|---|---|
| 可见光 | 分辨率预设、采集 FPS、水平 FOV、曝光模式 | 内参、畸变、裁剪与噪声；只开放已实际实现的参数 |
| 红外 | 640×512、采集 FPS、FOV、白热/黑热、显示范围 | 当前是合成热强度，不能标为实际摄氏温度或真实 NETD |
| 激光 | 扫描 FPS、水平/垂直 FOV、采样数、量程 | 坐标系、扫描策略与噪声；世界累积作为可选预览，原始出口保留单帧 |
| 云台 | 偏航/俯仰、速度、保持/真值跟踪、目标对象 | 限位、安装外参、零位和标定状态 |
| 视频输出 | 发布开关、码率、编码预设、地址 | 关键帧间隔、传输与重连；采集参数和编码参数分开 |

UI 从传感器能力描述生成控件：单位、范围、步长、默认值、读写、热更新/需重启。未实现或无法生效的项目显示原因并禁用，不做空开关。

参数编辑流程：修改草稿 → 显示变更 → 应用 → 服务端校验 → 返回实际生效值/版本。分辨率等重建采集链路的变更提示短暂重连；云台角度/调色板等可热更新。失败保留旧生效值，不能仅修改 UI。

## 7. 自由视角与设备移动

**可以做出 UE 风格自由观察。** 建议增加独立观察相机，而不是把云台镜头或无人机挪动来“看场景”。UE 的 DefaultPawn/SpectatorPawn 已具备无重力飞行观察的基础，具体输入和模式仍需在 WISEYE 实现。[Epic Pawn 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/pawn-in-unreal-engine)

| 模式 | 操作/用途 | 是否改变设备 |
|---|---|---|
| 自由观察 | 右键按住转向，WASD 平移，Q/E 升降，Shift 加速，滚轮调速 | 否 |
| 环绕对象 | 聚焦所选对象、拖动环绕、滚轮拉近 | 否 |
| 无人机跟随 | 跟随指定 drone_id，选尾随/侧看/俯视并调距离 | 否 |
| 机载观察 | 相机刚性附着无人机，体验第一视角 | 不改变飞行；只有注册为传感器才提供正式数据输出 |
| 云台传感器 | 查看设备实际传感器光心、FOV 与指向 | 控制云台才改变测量方向 |

输入模式必须显式互斥：“观察场景/操纵无人机/控制云台”。切换模式、松键、失焦或断连先归零旧输入；同一次 W 不能同时移动自由相机和无人机。文字输入框始终优先。观察相机可在物理悬停时继续移动。

设备位置也能像 UE 一样通过移动/旋转手柄、地面点选、数值输入改变，但放在**场景编排模式**。地面云台按真实挂接关系整体移动；不把 bottom/camera 等部件拆散。仿真运行时地面安装点默认锁定，云台只做机械允许的偏航/俯仰；若未来需要移动式平台，应建移动底座并记录外参变化。

第一阶段可先用受工作台管理的独立 UE 场景窗口交付自由观察，支持聚焦与切换。桌面内嵌完整 3D 画面与鼠标控制单列技术验证：评估本机纹理共享或 WebRTC/Pixel Streaming 的 UE5.8/显卡兼容性、输入捕获与延迟，不直接把编辑器窗口强塞进 PySide6。对外传感器 RTSP 与交互观察流分别设计。[Epic Pixel Streaming](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-pixel-streaming-in-unreal-engine)

## 8. 无人机：先单架顺手，再多架独立

单架控制：起飞、悬停、降落、手动速度/转向、航点航线、返初始点。起飞前明确目标高度、速度限额和碰撞检查。手动支持键盘和按住按钮；航线支持场景点选、坐标编辑、速度/高度/停留时间、循环及预览。

“悬停”“停止航线”“返回初始点”“重置整个场景”使用不同动作。当前 AirSim 的暂停实际是悬停，UI 标为悬停，不能标成物理时钟冻结；真正全局步进/暂停需要另行实现和验收。

多架从数据结构上采用 drone_id / model_id / dynamics_profile_id / initial_pose / route_id / controller_owner。外观尺寸与质量/惯量/电机参数分开，不能用切换 Mavic/Avata 外观声称两种动力学均已校准。

多架实施顺序：2 架独立起降/不同航线 → 4 架与性能预算 → 组操作。每机独立 API 对象、飞行状态、失联状态和录制标识，禁止继续硬编码 Drone1。

手动一次接管一架，切换接管先让旧机悬停再给新机输入。批量启动/悬停/降落必须显式选组并显示范围；组命令返回每架的成功/失败，不能一架失败仍显示全部成功。默认按已设间隔起飞，可支持明确的同时起飞策略。

多架能力不包含自动避障、编队规划、机间气动干扰或集群智能。需要这些时另立任务。第一轮验收先验证交叉航线/碰撞响应和实例隔离。

## 9. 初始布局与场景预设

地图资产只描述环境；场景预设描述这次仿真如何布置。选择地图后可新增/删除/复制设备，选择机型、数量、起始坐标、航向、相对地面高度、云台安装位置/高度/初始指向、传感器参数和航线。复制对象必须产生新 ID。

支持“点选地面放置、对齐地面法线/高度、移动旋转手柄、精确数值、保存预设”。验证对象是否入地、初始包围体重叠、航点是否合法、ID 是否重复、机型与动力学配置是否存在；地形高度采样不能默认 z=0。显示“相对地面高度”与“世界高度”的差别。

对用户默认米和度；内部 UE 厘米、AirSim NED 米、传感器 X前/Y右/Z上转换集中在适配层，写清 world/map/body/sensor 的 frame_id 和父子外参。外形缩放不进入传感器刚体坐标换算。

新增设备/改初始位姿只在编排/已停止阶段应用到新的运行实例；飞行中不瞬移。保存初始状态不覆盖当前动态位置；重开预设或重置应产生新的会话/时钟 epoch，历史数据不覆盖。

## 10. 开放接口与控制权

对外统一 WISEYE 对象与会话语义，内部仍以 UE 负责渲染/设备、AirSim 负责唯一动力学写入。增加协调层封装现有两端口；不让 UI 或扩展应用同时向两个后端写相同姿态。现有 v1 单设备命令保留适配，v2 增加目标 ID、能力发现与订阅。

| 数据/操作 | 建议接口 | 约束 |
|---|---|---|
| 传感器视频 | 保留 RTSP/H.264 | 稳定 sensor_id 到地址映射；新增订阅者不创建重复渲染 |
| 参数/场景/设备命令 | 有确认的版本化命令接口 | request_id、target_id、参数版本、已接受/执行中/成功/失败；actual values |
| 位姿/状态/事件 | 有界发布订阅 | session/run/epoch、设备 ID、时间与 frame_id；慢订阅者不阻塞飞控 |
| 点云/原始图像 | 本机二进制帧或共享内存，跨机再选网络传输 | schema、长度、序号、单位、坐标、丢帧统计；不长期用 JSON 点云做高吞吐出口 |
| 数据源发现 | sensor 列表、能力与地址 | 外部应用不硬编码 CH1/CH2 或 Drone1 |
| 原始录制 | 原始帧/码流 + 参数快照 + metadata + events | 新会话目录，显式记录丢帧/停止原因 |

建议未来地址形如 /sensors/ptz-01/visible；这是目标命名，当前地址仍为 CH1/CH2，实施时保留兼容别名。

每条数据至少携带 run_id、clock_epoch、sensor_id、frame_seq、capture_sim_time、capture_monotonic_time、frame_id、参数版本。RTSP 码流的显示序列与采集帧不能假定一一对应；先建立 PTS 与源帧映射，再提供旁路元数据。时间重置换 epoch，跨机器延迟需时钟同步或明确误差，未同步不报伪精确端到端延迟。

可见光/红外 RGB 渲染的 RTSP 是压缩观看通道。需要定量红外或无损实验时另开原始数据出口，说明当前红外只是合成热强度，8-bit H.264 不是温度测量。普通可见光/点云快照和真值位姿保留现有能力。

扩展应用默认只读订阅；需要控制云台或无人机时申请按对象划分的控制租约，界面显示拥有者、范围和过期时间；人工接管有明确优先级。一个对象同一时刻只有一个有效写入者，租约超时执行已定义的悬停/保持策略。

## 11. RTSP 与实时显示优化

**需要优化，但保留 RTSP 接口。** RTSP 本身并非目前唯一问题，已确认的成本在中间 JPEG/Base64、CPU 软件再编码、图像搬运、界面事件队列与多路渲染预算。当前已有异步 readback，不能再次把“改为异步读取”当成全新解决方案。

### 先把问题测清

分别测 UE 渲染、传感器采集新帧、JPEG/编码、发布、接收解码、UI 真正呈现的 FPS 和时延；统计 P50/P95、重复帧、丢帧、队列深度、GPU/CPU。一个接收间隔不能代表源端帧率，不能以重复发送缓存帧凑验收数。

桌面采用“只消费最新帧”的有界邮箱，图像按显示节奏刷新，后台小窗降显示刷新率，关闭的预览停止解码；对外正在发布的传感器仍按明确配置运行。保持传感器原始长宽比与像素查看能力，不为预览拉伸数据。

### 编码分两步

1. 先做低风险试验：选择硬件 H.264 编码，短 GOP、无 B 帧、受控码率和有界队列；保留软件回退。当前 GOP=1 每帧 I 帧，利于立即接入但压缩效率不高，建议测试约 0.5–1 秒关键帧间隔与首次打开时间，不能直接认定越小越好。
2. 完整数据面：UE render target → 颜色格式转换 → 硬件编码 → 发布器/MediaMTX → RTSP → 硬件解码/显示，移除 JPEG/Base64 和二次有损编码。GPU 纹理跨进程/编码器路径需要实际验证，不能只替换 libx264 就宣称零拷贝。图像/点云大数据与控制面分离。

本机记录的 GPU 是 Intel Arc B580；已只读检查安装 FFmpeg 的编码器列表含 h264_qsv，但没有在本轮执行硬件编码测试。优先评估 Intel QSV/oneVPL 的端到端路径，再测兼容性与负载；不要默认使用只适合其他显卡的方案。FFmpeg 文档提供 QSV 的码率、异步深度、低延迟和 GOP 配置，实际可用性仍需驱动/像素格式/设备初始化验证。[FFmpeg QSV 编码文档](https://www.ffmpeg.org/ffmpeg-codecs.html#QSV-Encoders)

### 多路预算

一组可见光 1080p30 + 红外 640×512p25，采集像素速率约 70.4 Mpixel/s（未含场景观察和其他开销）。增加一架无机载传感器的无人机不等于新增一组视频流；增加机载相机才增加对应的采集、渲染、编码与网络成本。传感器按独立输出启用与预览策略调度，低负载模式明确显示实际采样率。

### 验收目标（已批准方向，仍需实测达成）

- 选定测试场景/画质/硬件下，可见光 1920×1080 30 独立新帧/s、红外 640×512 25 独立新帧/s；30 分钟运行无无界积压。
- 本机观看端到端 P95 延迟目标 ≤250 ms；控制确认 P95 ≤200 ms；记录、推流和预览分开统计。
- 切换已开启通道目标 ≤1 s，首次接入目标 ≤3 s；实际受 GOP/解码初始化影响，先基准实测再定稿。
- 视频断流不阻塞飞行或云台控制；UI 显示过期。两个外部订阅者不导致重复 UE 渲染或编码。
- 双画面、点云、场景观察与两架/四架分别跑负载矩阵；不能用一个空场景通过就推及所有地图/多架数量。

## 13. 分阶段实施与审批范围

| 阶段 | 交付内容 | 验收核心 |
|---|---|---|
| A：单架工作台 | 四页结构、设备树、观察模式/输入互斥、传感器参数实际生效、初始位置保存、运行状态、独立 UE 自由观察 | 无需改 UE 源码或 Actor 才能布置并完成一次单架任务；观察时无人机不误动；重开预设重现初始位置 |

| C：多架与任务 | 2 架→4 架、独立初始位姿/航线/控制权、批量动作逐机回执 | 两架各自飞行，切接管旧机悬停，流与参数不串机，保存/重载一致 |

所有阶段不含算法运行、模型训练、复杂后处理、完整场景重建、自动避障、编队规划及尚不存在的雷达/事件相机真实仿真。
