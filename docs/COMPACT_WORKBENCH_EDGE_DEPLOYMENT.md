# 工作台精简与边缘部署评估（2026-10-30）

**状态更新：用户已明确放弃边缘盒子方案。下文部署评估只留作历史参考，不是当前执行计划。界面精简继续保留。**

## 本轮界面修改

- 删除工作台上方独占一整行的场景／连接／健康／键盘／画质控制。连接和推进异常统一显示在右上角状态；详细推进信息保留在运行诊断中，冻结检测及输入清零不变。
- 运行诊断保留设备栏底部入口；侧栏被折叠时，也能从资源设置的性能与画质进入。取消顶部重复的“诊断”。
- 已有画面工具栏新增“场景”菜单：环境与天气、性能与画质。前者打开原环境对话框，后者转到资源设置对应分组，不新建控制器或增加采集。
- 唯一键盘模式选择器移入原有控制归属条，保留驾驶和云台实例身份。原画质控件作为回读兼容对象隐藏，资源设置仍编辑同一实际档位。
- 五个导航分别为屏幕、场景建筑、设备网格、双向接口、设置滑杆。统一68×68逻辑点击区、24×24图标框与文字基线，图标不再重复。保留可访问名称、键盘焦点和原页面索引。

默认仍只打开GUI，不自动启动UE。此轮没有启动UE、重新编译或打包，不改地图、Fleet、红外和飞控命令。

验证：62项Qt回归通过；原生100%／150%布局检查及场景菜单、键盘控件归属、五个图标不同且几何一致的检查通过。证据目录 `evidence/ui-v4-20261030/compact-toolbar` 为未连接程序截图。1440×900／150%仍钳制到最小逻辑窗口，不能据此称适配该物理屏幕。

## RK3576 能否运行当前仿真

结论：**不适合作为当前完整UE城市仿真的承载设备**。这是基于硬件与当前工程依赖的可行性判断，没有在实际RK3576板上做性能测试；不等于任何UE项目都绝对无法在该SoC上运行。

[Rockchip RK3576官方简明数据表](https://www.rock-chips.com/uploads/pdf/2024.3.18/191/RK3576%20Brief%20Datasheet%20V1.2-20240311.pdf)列出Cortex-A72/A53、Mali-G52 MC3 GPU、6 TOPS INT8 NPU及视频编解码模块。NPU推理能力、视频编解码能力与UE三维渲染能力是不同指标；6 TOPS不能代替城市、阴影、红外／深度与多相机渲染。

[Epic City Sample官方说明](https://dev.epicgames.com/documentation/unreal-engine/city-sample-project-unreal-engine-demonstration)将该项目定位为重图形场景，推荐64GB内存、RTX2080／Radeon6000级或更高显卡、至少8GB显存及SSD。这是原版City Sample推荐值，**不是本项目裁剪版经验证的最低配置**，但说明它与RK3576的定位差距。

本项目还存在平台移植工作：现有Build-Release走Win64，当前运行包不能直接放到ARM Linux盒子运行；UE、ProjectAirSim及依赖需验证ARM目标编译和驱动支持，地图和材质需重新Cook。针对移动渲染大幅裁剪城市、材质、光照及传感器后或许可做另一款轻量演示，但已不是直接部署现有版本，也不能承诺保留当前红外效果和吞吐。

## 建议的部署分工

| 设备 | 工作 | 当前可行性 |
|---|---|---|
| 带独显的x86计算机／GPU边缘服务器 | 运行打包UE、ProjectAirSim、相机捕获、热像与GT生成 | 推荐承载当前项目；配置以实际地图和传感器负载验收 |
| 用户主机 | 控制界面、观察画面解码显示、接收样本或训练 | 可将主要渲染开销移到服务端；显示、解码和网络仍占少量本机资源，训练另算 |
| RK3576 | 可选视频接入／转发、设备协议适配、经RKNN转换后的轻量推理 | 独立移植与驱动验收后可用；它不能让仍在主机运行的UE自动卸载渲染 |

目标拓扑：用户主机控制台 ⇄ 有线局域网 ⇄ GPU仿真计算节点；RK3576仅按实际需要接入，不必为了远程运行额外串联一个盒子。

## 远程运行还需实施的工作

1. 将UE／AirSim本地控制协议包装成受管理的远程控制服务，保留设备身份、会话校验、断连清零和控制归属。
2. 图像采用适合低延迟的编码／传输链路，GT和标注按独立同组数据通道传输；不会因远程化就自动获得更高GT帧率。
3. 将“启动本机仿真”与“连接远程仿真”分开，明确远程会话是否由本客户端拥有；关闭本地界面不能随意结束别人使用的服务器。
4. 验收网络抖动、画面年龄、操作到反馈时延、带宽、多传感器和落盘速率；单向年龄需时钟同步或其他可靠测量方式。

**当前还不是填写远端IP就能完整控制的成品。** `WiseEyeBridge.cpp`控制服务绑定127.0.0.1；飞控的CONTROL_HOST也是127.0.0.1。50100训练服务可局域网提供数据，不能据此声称50051／50052已可远程控制。本轮没有更改监听地址或开放端口。优先在另一台Windows GPU计算机部署现有包并补服务层，之后再评估其他平台。
