# 建筑碰撞后粘住修复（2026-10-22）

## 问题与修复

现场 UE 和飞控接口仍能响应、仿真时间推进，但无人机贴在 CitySample 建筑上反复触发碰撞。修复前真实位置连续采样不变，反向输入也没有使其脱离。

Project AirSim FastPhysics 在碰撞响应中沿用上一状态的速度/加速度，同时清零输出加速度并保留旧姿态。持续接触时，本轮飞控产生的新速度和姿态被覆盖，可能进入粘墙循环。

新增 `third_party/patches/projectairsim-wall-contact.patch`：

- `StepPhysicsBody` 将本轮无碰撞预测状态传入接触响应，保留新飞控的线速度、角速度与姿态响应；阻挡及反弹仍由碰撞计算完成。
- 普通接触增加与原有着陆逻辑相同的 1mm 间隙，减少连续零深度碰撞。
- 保留真实碰撞、物理姿态、飞控和电机数据；没有关闭建筑碰撞或自动瞬移回出生点。

`scripts/Setup-ProjectAirSim.ps1` 在基础及 GC 补丁后应用此独立补丁，可重复执行。修复位于依赖的物理静态库中，需要重建 SimLibs 并重新链接 UE 插件；只更新 Python 或只点 Play 不会加载修复。

## 本机验证

- SimLibs、`testEditor` 实际构建成功。
- 原生 `FastPhysics*` 19 项测试通过，含新增的持续接触下新控制响应测试；44 项现有 Python 核心测试通过。
- 重复执行 `Setup-ProjectAirSim.ps1 -SkipBuild` 成功，补丁反向检查成功。
- 同一真实 CitySample 建筑连续三轮接触，分别记录到 54、53、51 次碰撞；按远离墙面方向输入后分别离开约 6.80、6.74、6.60m，仿真时间及控制持续正常。
- 撞击会改变机体朝向，因此测试每次将世界 X 方向换算为当时的机体前后/左右输入。并非宣称机体转向后固定按 S 一定远离墙面。
- 随后通过临时航点返回起飞区域并真实降落、disarm；Fleet 文件哈希保持不变。城市数量和位置采用用户现有文件，本轮为 1 UAV + 2 PTZ。

证据：[collision_recovery_live_20261022.json](evidence/collision_recovery_live_20261022.json)。首次试跑曾因测试脚本参数命名冲突停止；另两次测试因撞击后的高度/朝向变化或航点到达判断未满足而停止。最终固定重复接近、按世界方向施加输入，并在目标 0.85m 内主动悬停后完成上述验证；不把主动悬停算成自动航线自然完成。

本次验证不代表所有模型、建筑形状、高速撞击或长期多机碰撞均已通过。碰撞导致姿态变化、弹开和短时高度变化仍然可能发生；这是保留碰撞响应的仿真，不是自动避障。

## 使用与复测

本机已加载新插件。碰撞后松开持续顶墙的输入，再向远离墙面的方向控制；根据当前机头方向选择前后或左右。R 上升/F 下降保持不变。

另一台开发电脑更新代码后，先保存并关闭 UE，按 `INSTALLATION.md` 的依赖步骤执行 `Setup-ProjectAirSim.ps1`（不要加 `-SkipBuild`），再正常启动以重建并加载 UE 插件。

可选真实飞行回归（会起飞并接近建筑，不属于普通单元测试）：

```powershell
.\.venv\Scripts\python.exe -X utf8 tests\verify_collision_live.py --allow-flight --editor-log "E:\Projects\WISEYE-Studio\logs\collision_editor_20261022.log"
```

必须传入当前 UE 进程的实际日志。测试限定 CitySample、单无人机、已落地及文档中的原始起飞点；不改地图和 Fleet 文件。失败时尝试悬停并输出错误，需要检查飞行状态后降落。临时上传的测试航线仅在飞控内存中，测试后可在已落地时重新启动飞控服务清除。
