# WISEYE Studio 全套界面与交互改版方案 V3

日期：2026-10-21。**状态：用户已要求“按照方案开始修改”，主要界面交互已实施；实际交付与剩余项见 `UI_REDESIGN_IMPLEMENTATION.md`。本文为完整目标规格，不代表每项长期功能均已完成。**

本方案延续 V2 的“仿真平台 + 开放数据接口”定位。当前能力以 `AI_HANDOFF.md` 顶部、源码和最新验收证据为准，不能把旧设计文档中的愿景当成已实现功能。用户已确认采用 **专业深灰 + 蓝色强调**，默认布局为 **场景大画面 + 传感器缩略窗**，随后已授权按方案实施，完成情况以实施记录为准。

配套：`AI_UI_REDESIGN_HANDOFF.md` 为实施交接；`ui/wiseye-v3-review.html` 为离线可点击布局示意，使用模拟内容，不连接 UE。

## 1. 改版目标与当前问题

用户要解决的是“用起来顺手、画面看得清、参数不容易设错”，不是只换颜色。

| 当前情况（源码及 runtime_controls_final_20261021.png） | 改版决定 | 验收结果 |
|---|---|---|
| 三张大状态卡、模式行、健康行、对象行、说明行挤占高度 | 合并为一条运行栏，常态说明移入就地帮助 | 首屏无需滚动即可看到主要画面和关键动作 |
| 通道下拉、四个画面标签、勾选框重复控制显示 | 统一为画面工作区：添加画面 + 布局预设 | 一处决定显示内容，不存在互相冲突的选择器 |
| 四画面平均分配，图像区域偏小 | 场景主画面 + 三个传感器缩略图；可切双模态、四宫格、自定义 | 放大、并排、返回布局无需重新选源 |
| 按钮外观近乎一致，状态值也像按钮 | 主动作、次动作、危险动作、只读遥测采用不同组件 | 用户能区分可执行动作和只读数值 |
| 操作面板同时出现航线、驾驶、型号等 | 根据当前对象展示；机型和初始位置移到编排 | 工作台主要承担运行中的操作 |
| 名为 CH1 的画面随云台选择变化 | 画面绑定固定设备与传感器身份 | 看 ptz-02 时不会把已固定的 ptz-01 图像偷偷换掉 |
| 参数、实际值、应用状态分散 | 统一草稿编辑与服务端确认流程 | 切设备、断线、失败、晚回包都不会串参数 |

不扩展检测识别、训练、算法评估页面；不在本轮引入新的 UI 框架。保留 PySide6、UE、AirSim 和已验证的控制/视频链路。

## 2. 信息架构

四个顶级页面保留，并统一命名：**场景编排 / 仿真工作台 / 数据与接口 / 资源与设置**。

### 场景编排

- 左侧：场景资源、无人机、地面设备和航线列表。设备用显示名 + 固定 ID，型号是实例属性。
- 中部：场景预览与初始位置预览。当前表面放置仍需要独立 UE 窗口，按钮必须写“在 UE 中放置”，不能假装已支持桌面画面点选。
- 右侧：所选实例名称、型号、初始 X/Y/Z（m）、航向（°）、关联航线、云台默认目标。设备增删复制集中在这里。
- 底部：草稿变更数、保存预设、应用并重载。显示“需所有无人机降落后应用”，应用前列出影响对象。
- 区分地图资产、场景设备预设、个人窗口布局。保存窗口大小不覆盖设备初始位置。
- City Sample 卡片标“待下载 / 未准备”，保留操作指引；不显示可进入或已导入。保留用户当前 3 UAV + 2 PTZ，不恢复旧 2+2 示例。

### 仿真工作台

一个画面工作区，少量稳定的控制位置，详见下一节。

### 数据与接口

- 按设备分组的数据源表：设备、传感器、启用状态、输出状态、格式、原生尺寸/采样信息、地址、操作。
- 每行提供“复制地址”“查看接口”“保存原始单帧”；地址展开后显示，不占据工作台。
- 云台接口展示 SDK 示例入口、坐标单位、角度限位、速度超时说明、支持命令。当前本机接口没有多客户端排他控制权仲裁，不能显示已具有硬件级独占锁。
- 当前单帧 PNG/PLY + 元数据与未来连续录制必须区分。连续录制、会话回放尚未实现时不放可点击的假按钮。
- “关闭本地画面”“停用传感器”“停止发布”是三个概念；当前协议采集与输出联动，只展示实际可执行的组合开关。

### 资源与设置

- 显示：主题、字号、工作区布局恢复、快捷键说明。
- 性能：画质 / 均衡 / 节能，解释捕获目标、UE 帧率上限与画质影响；默认均衡。
- 资源：场景、机型及准备状态；只开放实际支持的导入流程。
- 诊断：UE 推进、飞行服务、视频发布、每路新帧、GPU（可取得时）、重连和日志。
- 不把端口、进程、路径等开发细节长期放在普通驾驶界面。

## 3. 工作台布局规范

### 默认结构（用户已确认：场景主导）

```text
├ 设备与数据源 ┬ 画面工作区：布局 / 添加画面 ┬ 当前对象 ┤
│ 搜索        │                            │ 名称 + ID │
│ 无人机 3    │       UE 观察主画面        │ 状态      │
│  云台 2     │                            │ 操作/参数 │
│   可见光    ├─────────┬────────┬─────────┤           │
│   红外      │ 可见光  │ 红外   │ 点云    │           │
│   激光雷达  │ 缩略图  │ 缩略图 │ 缩略图  │           │
├─────────────┴─────────┴────────┴─────────┴───────────┤
│ 事件 2   最近一条可处理提示       飞行服务 / 数据源状态 │
└────────────────────────────────────────────────────┘
```

建议尺寸采用 Qt 逻辑像素，不能用物理分辨率绕过 DPI：导航 48px，运行栏 40px，底栏 28px，外间距 12px，面板间距 8px。1920×1080、100% 时左栏约 220px、右栏约 320px；余下全部给画面。场景与缩略区高度初始约 70:30，可拖动。侧栏可折叠，宽度和布局记忆为用户偏好。

1600×900 可压缩左栏至 190px、右栏至 300px；逻辑可用宽度小于 1440 时默认折叠左侧树，右栏用可收起面板；1280×720 保证主画面和关键动作可用，其余参数在面板内部滚动。不能为了放下所有内容而把字体缩小到难以阅读。需实测 100%/125%/150% DPI，特别是 1920×1080 在 150% 下的逻辑尺寸。

### 布局预设

| 预设 | 布局 | 场景 |
|---|---|---|
| 场景主导 | OBS 主画面，VIS/IR/LIDAR 缩略图 | 驾驶、布置后确认、演示 |
| 双模态对比 | 同一 PTZ 的 VIS 与 IR 并排，OBS 可折叠小窗 | 观察目标与调参 |
| 多源监看 | 2×2，可混合 ptz-01 和 ptz-02 | 多设备实验 |
| 自定义 | 首轮提供拖动交换、移除、主画面指定、分割比例保存 | 用户常用任务 |

第一轮不承诺任意 IDE 式嵌套停靠。优先保证上述布局与拖动换位稳定，再考虑复杂停靠。

从设备树双击传感器或拖入工作区添加画面；提供等效“添加画面”菜单，不能只支持拖拽。一个工作区里同一源默认只放一次；允许共享到弹窗。保存布局记录源身份、位置、比例，不保存正在按下的键或控制接管状态。设备删除后保留“来源不存在”的占位供用户移除，禁止自动换成另一设备。

## 4. 传感器画面规范（本次重点）

每块画面包含三层：

1. **标题栏**：`云台 01 · 可见光`，次级显示 `ptz-01 / visible`；右侧“放大”“更多”。标题点击选中属性面板，不接管驾驶。
2. **内容区**：尽可能大，原比例适配，未连接/已停用/等待首帧/超时分别显示。
3. **轻量信息条**：原生尺寸、实际新帧率、帧年龄或最后更新时间。详细时间戳、序号、接收 FPS 放信息菜单。

标题栏的“更多”统一收纳：保存原始单帧、适应窗口、原始像素、移出工作区、弹出窗口、查看源信息。快照是常用操作，可在宽画面直接显示图标，但必须有文字 tooltip 和可访问名称。

### 不同类型的显示规则

| 源 | 显示规则 | 禁止误导 |
|---|---|---|
| 可见光 | 源 1920×1080，16:9，适应/1:1/显示缩放 | 预览缩小不等于改了输出分辨率 |
| 红外 | 源 640×512，5:4；保留适配留白 | 不拉伸到 16:9；合成强度不能标成实测温度 |
| 点云 | 等比例米制坐标，默认三维，俯视/正视/复位；有效回波/射线数 | 0 回波是合法空数据，不等于连接失败；不默认累积制造“更密”假象 |
| UE 观察 | 自由/全景/云台/跟随，跟随对象明确显示 | OBS 不是正式可见光传感器数据；移动相机不移动设备 |

双模态“等高容器”可以成立，但图像必须各自保持比例。联动显示缩放属于可选显示功能，不等于两路像素配准。两帧显示各自时间，未建立同步验收前不写“同步”。

视频过期时旧帧加明显“画面已过期 · 最后更新 …”遮罩；保留源身份，阻止把旧帧保存成新的实时采集。当前 2s 缓存/约 3s 健康策略可沿用，慢速点云的新鲜度阈值需考虑扫描周期，不能照搬视频阈值。新帧率没有可信序号/源时间时显示“未知”，不以 RTSP 收包速率顶替。

放大/返回/弹窗不重新启动同一路 FFmpeg。固定源键建议为 `(scene_session_id, device_id, sensor_id)`，传输地址从源注册表解析，不把 CH1 当全局唯一身份。多云台同时显示需补源注册与订阅管理；现有 Gallery 随所选云台切换，不具备完整跨设备固定画面能力。

### 显示负载策略

- 每源一个解码器，缩略图和放大窗共享最新帧；UI 不累计视频队列。
- 本地不再展示的源可在引用计数归零后释放解码器；外部 RTSP 订阅与传感器采集不能因此被关闭。
- 第一版最多同时展示四路，增加第五路时提示替换或关闭其他画面；这只是本地显示限制，不是设备总数限制。
- 缩略图可降低本地重绘频率；不能声称这必然降低 UE 捕获/GPU 负载。
- 按需捕获、硬编、低延迟 OBS 通道属于独立性能工程，需要测量和接口支持。当前性能档位值是上限，不是保证帧率。

## 5. 视觉与组件规范

推荐专业中性深灰 + 单一蓝色强调，避免大面积蓝色底板、发光、渐变、厚边框和每组重复卡片。照片/点云本身是视觉重点。

| Token | 建议深色值 | 用途 |
|---|---|---|
| background | #17191D | 应用背景 |
| surface | #202329 | 侧栏、主表面 |
| surface-raised | #2A2E35 | 输入框、浮层 |
| border | #424954 | 必要分隔与控件边界 |
| text | #F2F4F7 | 正文 |
| text-secondary | #B4BCC8 | 辅助说明 |
| accent | #78B1FF | 选中、链接、焦点 |
| primary-fill | #245DC0 | 主要按钮，搭配白字 |
| success / warning / danger | #76D6A0 / #F3C66A / #FF9292 | 状态文字与标记，搭配名称 |

这些为设计起点；实现需检查实际前景/背景组合的对比度，普通文字目标至少 4.5:1、焦点和大字至少 3:1。按钮禁用仍需能读清标签；颜色不能是唯一状态表达。首轮按已确认的深色主题实现；浅色主题仅保留为后续可选扩展，不是本轮必做项。

- 字体：微软雅黑 UI 或系统中文 UI 字体；正文/输入 14 逻辑 px，标签 13px，标题 18px；状态数字等宽数字。次级文字不低于 12px。
- 统一 4/8/12/16/24 间距，按钮与输入高 32px，主要起降动作 36px；圆角 6px，画面内不套多重圆角边框。
- 使用一套线性图标；重要动作保留中文文字。删除、放大等图标提供 tooltip、键盘焦点与可访问名称。
- 一个操作组最多一个实心主按钮。次要动作描边或文字；危险动作红色只用于删除/重置等有明确后果的操作。正常降落不应被误标为故障红色。
- 所有按钮具备默认、悬停、按下、焦点、禁用、执行中、失败状态。执行中按钮阻止重复提交，失败给出可操作原因。
- 电机 RPM、坐标、角度、帧率用只读字段或数值行，绝不使用禁用按钮来排版遥测。

## 6. 参数输入与启停

右栏顶部固定显示“正在编辑：云台 02 / ptz-02”。云台内设 **控制 / 传感器 / 信息**；传感器内用小标签 **可见光 / 红外 / 激光雷达**。避免右栏再套多层卡片。

参数按“常用”“高级”“只读信息”分组。单位紧跟输入框，名称不使用内部字段名。数值输入支持精确键入与步进；滑条只用于适合连续试调的参数，必须同时有精确数值。滚轮滚动面板时不能意外改变未聚焦数值。越界在字段下方显示允许范围，不静默截断。

### 首轮只能开放这些已存在的参数

| 对象 | 可编辑字段 / 现有范围 | 只读与说明 |
|---|---|---|
| 可见光 | 启用采集与输出；水平 FOV 5–120° | 1920×1080；捕获目标受性能档位影响 |
| 红外 | 启用；水平 FOV 5–120°；白热/黑热；合成噪声 0–0.1 | 640×512；合成热成像；噪声无物理单位 |
| 激光雷达 | 启用；水平/垂直 FOV 0.1–60°；量程 1–1000m；扫描频率 0.05–10Hz | 48×12 射线；低频允许长时间等待新扫描 |
| 云台 | 目标偏航 −180–180°、俯仰 −15–75°；保持/真值跟踪及目标 | 目标角与实际角分开展示；摇杆实时控制不进入参数草稿 |

范围来源为当前 UI，实施时必须与 UE 服务端校验再次对齐，服务端为准。曝光、焦距 mm、温度量程、分辨率任意修改、激光线数、独立编码码率等尚未完成的能力不做可编辑假项。未来 capability schema 可提供范围/单位/热更新标志，但不能为第一阶段 UI 改版强行重写全部协议。

### 统一编辑事务

1. 表单显示服务端确认值；修改生成该设备、该传感器的本地草稿。
2. 修改字段旁标记变化；底部固定显示“2 项未应用”，按钮 **应用更改 / 撤销草稿**。撤销是回到实际值，不是恢复出厂。
3. 点击应用仅提交当前传感器；请求记录设备 ID、传感器 ID、请求 ID、提交快照、会话代次。等待中不覆盖新输入。
4. 服务端确认后更新“实际生效值”；若提交后又编辑过，保留新草稿和未应用标记。
5. 失败保留草稿和旧实际值；超时显示“结果待确认”，先查询实际状态，不能无条件自动重复动作。
6. 切换对象保存独立草稿并显示未应用标记；晚到的 A 设备回包绝不更新 B 设备。退出有未保存草稿时只在丢弃前提示。
7. 运行时应用与保存为场景初始参数分开。当前会话参数不持久化，未补配置路径前只能显示“本次运行有效”。

启用开关也属于当前传感器草稿，点击“应用更改”后才真正启停；开关旁显示实际“采集中/已停用”，避免草稿看起来已经生效。停用造成外部输出中断的影响在该行说明，不为每次数值修改弹确认框。

## 7. 飞行控制、云台和输入焦点

必须分离：**属性选中对象、手动驾驶对象、云台控制对象、云台跟踪目标、画面数据源**。点击红外图像只选其属性，不切换驾驶对象。

### 无人机面板

- 顶部：`uav-02 · Avata` + 当前飞行状态；接管按钮明确“接管 uav-02”。本机接管是 UI 输入归属，不宣称服务端已具备多客户端锁。
- 常用操作：起飞 / 悬停 / 降落。地面时起飞突出；飞行时悬停和降落保持可见。动作发出后展示该机的执行过程，不能以请求收到即当成完成。
- 下方“手动驾驶 / 航线任务”两个模式区域。手动区保留按住运动按钮及键盘帮助；航线区显示航线名、绑定机、进度、开始/暂停航线并悬停/继续航线/停止任务。
- 不把暂停航线叫“暂停仿真”。复位航线、重置设备初始位置、重置场景是不同操作，分别说明条件与后果。
- RPM 为四电机只读遥测，默认折叠到状态详情；保留真实转速和落地解除解锁逻辑，不恢复 O 键假启停。
- 型号和初始位置放编排页，运行时只读。
- 多架用左侧状态列表，不一次展示三套驾驶按钮。批量控制作为后续独立功能；若实现，显式选组、显示范围并逐机返回结果，不把单机按钮偷偷变为全体动作。

### 云台面板

- 模式用分段选择 **保持 / 手动 / 真值跟踪**；模式切换需要映射明确服务端命令和确认，不能只有本地高亮。
- 手动：比例摇杆、角度目标输入、实际角；摇杆松手回中，失焦、换对象、关闭弹窗、断连立即归零，保留 300ms 速度看门狗。
- 跟踪：目标无人机下拉 + “开始跟踪”，显示当前实际目标和指向误差。明确是 UE 真值指向，不是视觉识别跟踪。
- 如果手动操纵会退出跟踪，接管时明确提示一次，并在服务端确认后更新状态；不能同时显示“跟踪中”又持续手动写入。

### 键鼠统一

观察模式：OBS 内按住右键 + WASD、Q/E；驾驶：W/S 前后、A/D 左右、R/F 升降、Q/E 转向；云台：方向键。只在对应已接管上下文生效。输入框、下拉、表格编辑优先，不吞掉输入字符。Esc 释放本地持续输入并请求停止当前手动运动，不等同停机/场景复位；执行结果仍需反馈。

切换驾驶对象先清旧输入并确认旧机状态适合交接；旧机仍在航线飞行时不能悄悄打断，必须显式接管。窗口失焦不继续发送按住运动。切页面不应隐式让无人机起飞或换目标。

## 8. 航线编辑

- 从编排和无人机面板都可进入同一编辑器；顶部固定航线名称、绑定无人机与“草稿/已上传/正在执行”状态。
- 左侧航点表，右侧 XY 等比例预览；表格与拖点双向选择；明显标出起点、终点、当前执行点。
- 首轮沿用现有 2–128 点、速度 0.2–15m/s、单次/循环。坐标采用世界米制 Z 向上；不是离地高度，不能标成 AGL。
- 新增/插入/删除/上移/下移；撤销/重做作为独立小改动验收。输入非法值在对应行提示，不到最后上传时才报错。
- **保存草稿 / 上传到 uav-02 / 执行航线** 分离。上传成功不自动执行；执行前展示对象、航线版本与起飞条件。
- 运行快照与编辑草稿分离；正在执行时编辑不改变当前任务。未来在线改航线另立协议与安全状态设计。
- 3D 地形高度、避障、停留时间、批量分配、编队规划未实现时不画成已可用。现有逐点飞行拐角会减速，应在帮助中准确描述。

## 9. 状态、异常与反馈

| 状态范围 | 应呈现的内容 | 行为 |
|---|---|---|
| UE | 未连接 / 连接中 / 推进正常 / 推进停滞 | TCP 已连接不等于仿真正在跑；保留 tick 看门狗 |
| 飞行服务与每架 UAV | 待命、起飞中、悬停、手动、航线、降落中、失联 | 单机状态不能覆盖全局所有机 |
| 每个源 | 停用、等待首帧、正常、过期、解码失败 | 画面就地显示原因与重试入口 |
| 参数 | 未修改、草稿、提交中、已确认、失败、结果待确认 | 不把未知状态显示成成功 |

常态状态缩成运行栏与底栏；发生故障才展开可操作提示。普通成功用短暂轻提示；错误留在相关控件附近并写事件列表；需要持续关注的故障不能只闪一次。日志按设备、级别、时间筛选并合并重复信息。

**首轮只改变呈现，保留当前运动拦截策略。** 当前实现可能将传感器过期汇总为全局不健康；后续可拆分为推进/飞行/数据三类健康并制定动作矩阵，但必须单独评审和回归，不能为了“按钮可点”直接取消已有保护。降落/停止等恢复动作的可用性需单独验证，不跟普通新运动命令一刀切。

不要把本地 TCP 响应耗时标成视频端到端延迟；不要把 45 FPS 上限显示成正在达到 45 FPS。指标不支持时显示“未测量”。

## 11. 验收清单

1. 1920×1080、1600×900、1280×720 及 125%/150% DPI 截图；没有文字裁切、按钮重叠或主动作被遮住。常态四页面结构一致。
2. 默认场景区明显大于单个缩略图；双模态 IR 保持 5:4、VIS 保持 16:9；最大化返回后布局与源不变。
3. 同时查看 ptz-01 VIS 与 ptz-02 IR，改变驾驶对象、属性选择、跟踪目标，画面身份均不漂移。
4. 同源缩略图与弹窗同时打开只有一个解码器；反复开关、切布局后队列有界，无累积解码进程。
5. 两云台各修改不同传感器，未应用草稿独立；模拟断线、晚回包、失败与提交后继续编辑，实际值和草稿正确。
6. 输入框输入 WASD/QE/数字、滚动表单不会驱动物体或误改未聚焦参数。按住摇杆/键盘时失焦、切对象、关闭面板会停止持续输入。
7. 起飞/悬停/降落和航线只影响明确对象；继续验证两机型实际 RPM 与落地 disarm；3+2 配置不被改写。
8. UE 停止推进但 TCP 正常时仍显示异常；一路视频过期不能显示正常实时画面。任何健康策略变化另有动作矩阵与测试。
9. “保存原始单帧”保存正确源的原生数据和身份元数据；1:1、缩略和布局变化不改变 RTSP 输出尺寸。
10. 同场景、同性能档、同画面数比较改版前后：有效新帧率、GUI 响应、CPU/GPU/内存、解码器数量；30 分钟监看检查资源增长。性能结果附测量条件，不把短测当稳定保证。
11. 窗口布局重启恢复，外接屏移除后弹窗可回到可见屏幕；恢复布局不自动接管、起飞或执行航线。
12. 所有可点击功能有真实路径，未实现连续录制、任意传感器导入、City Sample、避障、跨客户端排他权不得冒充已完成。

本规格初次交付时仅为设计材料；用户随后已授权实施并完成主要交互及多项真实联调。上述清单仍为完整验收目标，具体已通过项目与未完成范围见 `UI_REDESIGN_IMPLEMENTATION.md`，不能把整张清单标为全部通过。
