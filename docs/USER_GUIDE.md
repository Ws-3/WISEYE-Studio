# WISEYE Studio 使用指南

## 独立运行包（2026-10-23更新）

已获得独立ZIP的用户：完整解压到本机SSD，双击 `WISEYE/WISEYE.exe`，选择场景并点击右上角“启动仿真”，不需要另装UE、VS或Python。设备就绪后再起飞，退出前先降落。缺VC++运行库时使用随包 `Simulation/Engine/Extras/Redist/en-us/vc_redist.x64.exe`。配置和日志默认在 `%LOCALAPPDATA%\WISEYE`。当前内测包含原始/测试场/真实城市，尚无在线更新器。

本机成品与完整校验、构建/限制见[RELEASE_BUILD.md](RELEASE_BUILD.md)。下方PowerShell/VBS启动方式面向源码开发环境，独立包无需使用。

更新：2026-10-22。本指南对应当前 V3 四页界面与已接入的 City Sample 小城市。旧文档中的单画面、固定两机两云台、城市未下载等内容属于历史记录。

## 每天如何运行

本机仓库：`E:\Projects\WISEYE-Studio`；UE：`E:\Programs\UE_5.8`，当前验证版本 5.8.4。环境已配置，不用每天安装依赖。

1. 如果要同步代码，先保存并关闭编辑器，执行 `git status`，处理自己的改动后再 `git pull --ff-only`。有冲突时按 [Git 工作流](GIT_WORKFLOW.md) 处理，不要强行覆盖本机文件。
2. 城市场景双击 `Start-CitySample.vbs`；原始场景双击 `Start-ProjectAirSim.vbs`。两者隐藏后台命令行。只启动一个 WISEYE UE 编辑器。
3. 等 UE 自动播放、城市缓存处理完成，再双击 `Start-WISEYE-Studio.vbs` 自动连接；也可打开 `Start-Desktop.cmd`，点击右上角“连接仿真”。桌面连接 UE 50051、飞控 50052。工作台直接预览UE最新缓存帧；8554的RTSP保留给外部应用。
4. 确认顶部显示正确场景、已连接、UE 正在推进，且传感器画面持续更新。无人机初始为地面待命；连接成功不会自动起飞。
5. 若 UE 已在运行，直接打开桌面连接。切换地图用“场景编排”，不要重复启动脚本来强行切图。

诊断时可在仓库 PowerShell 使用：

```powershell
.\Start-ProjectAirSim.cmd -Scene city -SkipBuild
.\Start-Desktop.cmd -Connect
```

代码更新包含 UE C++ 改动时，先保存关闭 UE，运行 `scripts\Start-WISEYE.ps1 -BuildOnly`，成功后再启动；`.vbs` 快捷入口跳过编译，不能代替首次构建。首次城市缓存可能明显卡顿，等画面稳定再操作。当前是开发环境，尚未交付免装 UE 的成品安装包。

## 仿真工作台与传感器画面

默认“场景主导”：大画面观察城市，下方缩略图显示可见光、红外与点云。可切“双模态”或“多源监看”，画面右上角有放大和更多操作，可弹出、按原始像素查看、替换或移除；拖动画面标题可换位，拖动分隔条可调整比例。最多同时保留四个来源，弹窗复用该来源的解码器。

| 来源 | 原始数据 | 用途 |
| --- | --- | --- |
| 可见光 EO / CH1 | 1920×1080 | 云台可见光相机 |
| 红外 IR / CH2 | 640×512 | 最小热强度模拟，支持白热/黑热 |
| UE 观察 / OBS | 960×540 | 独立观察视角，便于控制与检查场景 |
| LIDAR | 单次扫描的米制点云 | 查看真实碰撞回波，不累计成历史轨迹 |

预览缩小不会改变原始视频分辨率。编码流帧率、独立新渲染帧率和窗口刷新率不同；重复播放同一张图不能算传感器产生了新帧。界面“新帧”Hz来自UE完成缓存的计数，不是窗口实际独立显示帧率；“接收于多久前”只说明本地最近收到了图，不代表它刚刚在 UE 中采集。最新完整链路实测与判断方法见 [传感器延迟报告](SENSOR_LATENCY_REPORT.md)。

画面绑定固定 `device_id/sensor_id`；在树中选中对象只是编辑属性，不会自动接管驾驶，也不会把现有画面换成另一套设备。

## 无人机驾驶与航线

1. 在右侧“驾驶”选择无人机，点击“起飞”，等待动作完成。
2. 使用手动飞行时点击“接管手动驾驶”；按住面板方向按钮，松开停止输入。键盘操作需把顶部输入对象切到无人机，且焦点不在坐标/参数输入框中。
3. 系统与UE的无人机键盘统一：W/S 前后、A/D 左右、**R上升 / F下降**、Q/E 转向；箭头键不再控制无人机升降。可用悬停按钮制动保持；降落完成后电机与旋翼停止。
4. “编辑航线 / 管理任务”中选择对应无人机、编辑航点，先上传确认，再单独执行。上传不等于起飞或开始航线；执行要求已起飞且当前动作结束。
5. 航线暂停/停止会制动悬停；继续按当前任务状态恢复。初始位置改动后，应重新检查航点位置和高度。

RPM 来自 AirSim 物理电机遥测；旋翼会有视觉混叠，不能通过肉眼转了几圈判断实际转速。无人机外观尺寸按项目标定，当前动力学不代表经过厂商标定的 Mavic/Avata 飞行模型。

城市没有自动避障。航点需人工检查建筑、树木和地形；本轮验证了起降与短距离手动运动，没有验收任意城市航线。

## 云台与观察视角

“驾驶对象”和“云台对象”分别选择；给另一套云台编辑参数，不会自动改变当前控制对象。

云台面板可选择跟踪目标与跟踪开关。拖动/按住摇杆控制转动，松开停止输入；手动转动会退出跟踪。“停止并保持”清零输入并关闭跟踪。方向键需顶部输入对象为云台且输入框未占焦点；水平最高30°/s、俯仰20°/s，远程输入超过300ms未续发会停止。

顶部观察视角可选总览、自由观察、无人机跟随、云台视角。自由观察与真实设备运动分开：在 UE 视口按住鼠标右键，用 W/A/S/D 平移、Q/E 升降，Shift 加速；桌面观察画面可激活独立观察控制。观察模式的 Q/E 是升降，无人机驾驶模式的 Q/E 是转向，先确认当前输入模式。

外部云台接口、坐标与SDK示例见 [GIMBAL_INTERFACE.md](GIMBAL_INTERFACE.md)。当前跟踪为仿真真值指向，不是视觉算法闭环。

## 各传感器参数

选中具体设备下的传感器，再到参数页编辑。可见光、红外、LIDAR 分别启停，分别应用参数；关闭显示卡片只停止本地显示，不等于停用传感器。

- 可见光：启用、视场角。
- 红外：启用、视场角、白热/黑热、噪声。
- LIDAR：启用、水平/垂直视场、量程、扫描频率。扫描频率范围0.05～10Hz；点云不走RTSP。

编辑后点应用，等对应设备的确认；失败/断线不会把草稿当作成功。其他设备的参数草稿独立保留。当前传感器参数主要在本次运行中生效，不能把窗口布局保存当作参数保存。红外不是物理热辐射测温，城市材质也没有逐栋建筑温度模型。

## 场景编排与多设备

城市当前可选“City Sample · 小城市”，此外还有原始场景与通用测试场。变更配置后，所有无人机先降落，再保存并加载所选场景；加载会断开并重建仿真连接。

通过“新增 / 管理场景设备”统一新增、复制或修改完整无人机/云台实例，设置名称、型号、位置、初始偏航及云台目标。默认实例保留，每类最多四个；配置以 `ue5/WISEYE/Config/WISEYE/Fleets/<scene>.json` 的实际内容为准，不按旧文档数量恢复。当前本机城市是一机一云台。

场景编排坐标以米、Z向上显示；UE/配置内部部分字段以厘米存储。UE表面取点需要真正加载设备所在街区。City Sample 的下层碰撞块与可见人行道高度不同，不能在未加载的远景代理上直接确定安装高度。云台作为整体移动，保持总高80cm及内部轴向关系。

设备初始位置、俯视示意和“表面取点”列表均跟随当前场景已保存的全部设备。“管理全部设备”新增、复制或删除后，点击保存会立即更新列表；新增设备尚未加载到UE时，先加载场景再取点。选择设备后，“当前X/Y贴合表面”或“到UE点击放置”只修改该设备的草稿；保存初始布置、加载场景后才实际移动。City Sample取点包含FastGeo道路碰撞，避免误中下方隐藏平面；仍需加载所选街区，并核对最终落点。

Fleets保存完整实例，保存坐标只按设备ID更新改过的位置，保留型号、旋转和跟踪目标。命名位置预设可记录当前实例位置；读取旧两设备预设时保留额外设备，预设不会创建或删除实例。当前本机城市为1机2云台，设备数量以实际文件为准。多机批量编队、自动避碰以及4+4长时性能尚未验收。

## 保存数据与外部应用

“数据与接口”查看各设备的数据地址和控制接口；外部应用可订阅RTSP，默认路径为 `rtsp://127.0.0.1:8554/CH1`、`CH2`，观察为`OBS`。额外云台使用 `<ptz-id>/CH1` 与 `<ptz-id>/CH2`。工作台本身使用原生JPEG缓存预览，避免额外重编码延迟；两者分辨率和设备身份一致。控制接口为JSON Lines；详细协议见 [PROTOCOL.md](PROTOCOL.md)。

单帧保存按所选传感器导出 PNG 或 PLY，并带设备/场景元数据；输出在 `ue5/WISEYE/Saved/WISEYE`，可从资源页打开。连续录制、回放、检测和算法处理由后续扩展完善，当前不应把单帧导出当作连续录像。

## 延迟与卡顿怎么判断

2026-10-22城市渲染设置补充：若UE显示“RAY TRACING GEOMETRY — ALWAYS RESIDENT MEMORY EXCEEDS 20% OF THE BUDGET (83MiB / 400MiB)”，指常驻光追几何超过该池预算的20%提醒线，不是整块GPU显存耗尽，也不能单凭它判定卡顿根因。项目现默认关闭运行时硬件光追（`r.RayTracing.Enable=0`、`r.Lumen.HardwareRayTracing=0`），保留编译支持和原生传感器尺寸；城市光照/反射观感可能改变，画质档也不自动开启硬件光追。当前编辑器已应用并读回0，无需重启；下次启动从DefaultEngine.ini读取。按需切换依据[UE官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/hardware-ray-tracing-in-unreal-engine)。本次修改时PIE已停止，仅验证开关生效，尚无关闭光追前后的运行帧率对比。后续仍卡时需分别观察UE帧耗时和传感器采集频率；节能档视频源约10/10/8Hz，不能把低采集频率误认为旧帧积压。

“已连接”仅说明网络通；“UE正在推进”说明仿真Tick在推进；持续收到图也可能是重复的旧源帧。遇到明显滞后，先停止连续操控并确认画面恢复，再按以下顺序排查：

1. 城市是否仍在编译着色器、网格或纹理缓存，UE是否真的在Play。
2. 顶部是否为节能档。城市场景默认节能，保持原始分辨率，降低捕获频率与渲染负担；高画质未必更实时。
3. 是否重复开了 UE、桌面窗口、弹窗或外部 RTSP 播放器；只保留需要的监看画面。
4. 看源新帧率和状态推进，不能用“接收于0秒前”断言没有延迟。新预览会跳过重复源帧，源停滞2秒会提示过期。

2026-10-22修复后，本机城市节能档40秒单窗口实测：可见光内容年龄中位205ms/P95269ms，IR184/251ms，观察187/271ms；保留1920×1080、640×512、960×540。点云只对显示中的来源以100ms间隔查询，始终限制每设备一个在途请求。外部RTSP播放器延迟单独评估，不能直接套用工作台数据。完整证据和测量口径见 [SENSOR_LATENCY_REPORT.md](SENSOR_LATENCY_REPORT.md)。

本机局域回环测试不能代替另一台电脑的网络测试；远端部署还会增加网络抖动。当前延迟统计到Qt画面绘制，不包含显示器扫描输出。

**打包UE不会自动消除系统预览的滞后。** 打包可减少编辑器额外开销，现有“场景捕获→GPU读回/JPEG→网络读取→Qt显示”仍然存在。工作台已经直连最新JPEG帧，跳过RTSP重编码；当前节能档采集10/10/8Hz，本身约每100/100/125ms才有新画面。可在负载允许时试均衡档20/15/10Hz；GPU已吃紧时继续提高采集率可能更慢。后续低延迟优化应测量采集时序、读回/编码与显示耗时，减少图像拷贝；更紧密的GPU纹理共享需要专门实现，和最终打包部署分开推进。上次单窗口约0.2秒数据不代表本轮新增第二云台后的新性能保证。

## 结束与换电脑

**撞建筑后无法移动：** 2026-10-22 已修复 FastPhysics 连续碰撞时覆盖新飞控响应的问题。本机已重建插件并完成连续撞墙、脱离和降落验证。先松开顶墙输入，再根据当前机头方向控制无人机远离墙面；碰撞仍可能改变姿态和高度。另一台电脑须重建 AirSim SimLibs 及 UE 插件才会生效，详情见 [COLLISION_RECOVERY.md](COLLISION_RECOVERY.md)。

结束前先让各无人机降落、确认停桨，再关闭桌面并停止UE播放；只有在编辑器改过场景时才保存地图，不需要把每次运行保存成新的场景资源。

新电脑先按 [INSTALLATION.md](INSTALLATION.md) 安装依赖。City Sample 原始资源和插件源码不通过本项目Git公开同步；另一台电脑需获取同版本资源，再按 [CITY_SAMPLE_SETUP.md](CITY_SAMPLE_SETUP.md) 补装。Git同步自己的代码、配置与受管理地图时，World Partition外部Actor不能漏掉。不要上传`.venv`、Saved、日志、缓存或凭据。
